# 06 · 安全红线与成本纪律（Safety Red Lines & Cost Discipline）

> 本文件优先级最高：与任何其它技能冲突时，以本文件为准。
> 执行者：`SafetyGuard`（引擎）+ `ToolRegistry` 权限/预算检查（Harness）+ 审计日志（哈希链）。

## 1. 六条红线（违反即拒绝，无例外）

1. **动作白名单**：只能调用 `cfg.safety.allowed_playbooks` 中的 playbook 与
   `ToolRegistry` 中的工具；未注册工具一律拒绝；
2. **预算硬门**：labels / compute / tokens / updates 任一超出剩余额度 → 拒绝执行，
   不允许"先跑后补"；
3. **网络隔离**：默认 `allow_network=false`，系统运行期禁止任何 HTTP/DNS；
   唯一例外是显式配置的 LLM provider（openai_compat）与显式 `swanlab online`；
4. **不触碰隐藏测试**：系统永远不能读取 `hidden_by_chunk`/平台隐藏标签；
   标签只能通过 `LabelOracle` 按预算获取；
5. **kill-switch**：`STOP` 文件存在时停止一切自主更新（回滚除外），并记录原因；
6. **高危动作升级**：`NOVEL_CLASS_EXTEND`、`RETRAIN_MIXED` 等 high-risk 动作必须
   在 `Decision.safety` 中记录 escalation；LLM 不得自我批准，批准权在 loop/人类。

## 2. 成本纪律（每一轮决策都要遵守）

| 规则 | 具体做法 |
|---|---|
| 三本账 | 每个决策记录 `Cost(compute_units, labels, tokens, wall_s)`，预算前后快照写进 `Decision.budget_before/after` |
| 单位增益 | 记录 `Δ指标 / compute_units`、`Δ指标 / labels`，低成本高增益动作优先 |
| 预算余量 | 实验前保留 ≥1.5 倍估算成本；`labels_left < 2×probe_labels` 时停止实验 |
| token 上限 | LLM 驱动单次决策 ≤ `max_tokens_per_decision(20000)`；超限立即降级确定性 |
| 失败预算 | 连续失败 ≥ `max_consecutive_failures(3)` → 收手，等待下一阶段 |
| 记录成本 | 写入 1 条指标 < 5 ms、记录系统不占算力预算；但禁止把观测写入放进内层训练循环 |

## 3. 权限矩阵（工具级）

| 工具 | 类型 | 风险 | 预算消耗 | 拒绝条件 |
|---|---|---|---|---|
| `inspect_drift` / `budget_status` / `list_registry` / `query_history` / `propose_candidates` | 只读 | low | 0 | 未知工具/参数非法 |
| `diagnose` | 预算型 | low | 可能 labels | 诊断器不可用 / 预算不足 |
| `shadow_eval` | 只读评估 | low | 0（可选探针除外） | 实验不存在 |
| `run_experiment` | 写 | medium | compute/labels | 白名单外 / 预算不足 / phase 更新次数用满 / kill-switch |
| `evaluate_candidate` | 评估 | medium | 可能 labels | 候选不存在 / 门禁无法计算 |
| `request_labels` | 写预算 | low | labels | 超预算 / 无 oracle |
| `deploy` | 写模型 | high | 0 | 门禁未过 / kill-switch / 高危未记录 escalation |
| `rollback` | 写模型 | high | 0 | 目标版本不存在 / 无历史版本 |

## 4. 反例（真实会出事故的写法）

- ❌ "先跑实验，预算后面再算" —— 预算硬门必须**前置**检查；
- ❌ "模型自己判断可以上线就调用 deploy，不查门禁" —— 门禁是硬约束，不是建议；
- ❌ "网络请求失败就无限重试" —— provider 必须快速失败并降级（默认 retries=0）；
- ❌ "高危动作把 escalation 日志打在 stdout" —— 必须进 `Decision.safety` 与审计日志；
- ❌ "为了好看把失败实验从记录里删掉" —— 失败记录同样是"全部迭代实验"的一部分；
- ❌ "LLM 直接改配置/改预算"——配置与预算对 LLM 只读，工具参数有 schema 校验。

## 5. 审计要求

每个决策必须能从以下链路完整追溯（缺一不可）：

```
Decision(run_id 引用) → RunRecord/实验记录 → 指标(MetricPoint) + 成本(Cost)
   → 代码 commit + config_used.json + seed → SwanLab run（如启用）/ 本地镜像
```

- 审计日志：`experiments/audit/{run_id}.jsonl`，sha256 哈希链，`verify()` 必须为 true；
- 记录不可篡改：本地 JSONL append-only，SQLite 只 upsert 不 delete；
- 所有降级/告警写入 `tracker_warnings.jsonl`，不得静默吞异常。
