# 00 · 技能索引与总则（Skills Index）

> 技能包版本：v1.0（与 `src/core/config.py::DEFAULT_CONFIG` 对齐）
> 用途：① 注入 LLM 驱动的 system prompt；② `DeterministicDriver` 的可执行规则来源；
> ③ 作为评分材料证明"策略有章可循、可审计、可复现"。

## 文件索引

| 文件 | 技能 | 何时用 |
|---|---|---|
| `01_漂移分诊.md` | 漂移分诊（Drift Triage） | 每个窗口监测后，判断"是否值得干预" |
| `02_Playbook选择矩阵.md` | 动作选择（Playbook Matrix） | 诊断完成后，把 `kind` 映射到候选动作 |

| `06_安全红线与成本纪律.md` | 安全红线与成本纪律（Safety & Cost） | **每一轮决策前必读**，优先级最高 |

## 总则（优先级从高到低，冲突时上位规则胜出）

1. **安全 > 成本 > 增益 > 速度**：任何会突破预算、动作白名单、网络隔离的红线动作
   一律拒绝；拒绝也是合法决策（记为 `NOOP` 并写 rationale）。
2. **无证据不动作**：没有监测/诊断证据就不更新模型；`benign`、`repair` 阶段优先
   `NOOP` 或 `ROLLBACK`，不要为了"有动作"而硬跑实验。
3. **先便宜后昂贵**：默认 `cheapest-first`；只有高严重度 + 高先验时才升级到
   `FULL_FINETUNE_REPLAY` / `RETRAIN_MIXED` / `NOVEL_CLASS_EXTEND`。
4. **一次只改一个变量**：一次决策最多做一个候选实验；禁止同一窗口并行跑多个
   重型 playbook。
5. **全部记录**：每一步决策必须产生 `RunRecord`/指标/成本记录；没有记录的动作
   视为没发生（不可审计 = 不可接受）。
6. **可回滚**：上线前必须存在可回滚的上一稳定版本；否则先 `SHADOW_ONLY`。
7. **预算硬约束**：labels/compute/tokens/updates 任一耗尽即收手，转 `NOOP` 并
   在 rationale 写明"预算耗尽"。

## 输出协议（LLM 驱动时）

每一步只能输出一个 JSON 对象：要么调用一个工具
`{"thought": "...", "tool": "<tool_name>", "args": {...}}`，
要么给出最终决策
`{"thought": "...", "final": {"chosen_playbook": "...", "action": "...",
"reasoning": "...", "deploy": false, "version": null, "outcome": {...}}}`。
`chosen_playbook` 必须取自本轮 `candidates` 中的 playbook（或 `NOOP`），
否则该决策会被 Harness 判定为非法并回退确定性策略。
