# 03 · 实验设计与预算（Experiment Design & Budget）

> 原则：**一个实验只回答一个问题**；预算硬约束优先于"想试试"。
> 工具：`budget_status` → `propose_candidates` → `run_experiment` → `evaluate_candidate`。
> 依据：`budget`（labels_total=220、compute_total=220.0、tokens_total=120000、
> updates_total=40、per_phase_updates=3、probe_labels=6）。

## 1. 实验四件套（缺一不可，写进 `Experiment`/`RunRecord`）

1. **假设**（hypothesis）：一句话说明"改什么 → 预期哪个指标怎么动"；
   例："目标域统计量仿射校准可恢复 4~8pt macro-F1"。
2. **参数**（params）：playbook 名 + 关键超参 + 随机种子 + 使用数据量；
3. **验收指标**（metrics）：至少 `probe_macro_f1`、`pred_stability`、
   `class_recall_min`、`cost`（引擎契约 §4.3），外加运行耗时；
4. **结论**（summary）：增益 / 成本 / 是否过门禁 / 失败原因，一句话写清楚。

## 2. 预算分配纪律

| 资源 | 总量 | 建议分配 | 说明 |
|---|---|---|---|
| labels | 220 | 监测探针 ~40%（每 `probe_every=2` 窗口×`probe_labels=6`）<br>诊断 ~15%<br>适应实验 ~45% | 先保监测，再保实验；不允许把 labels 花在 NOOP/benign 阶段 |
| compute | 220.0 units | 单次实验 ≤ 40（`max_cost_per_update`）<br>每个 phase ≤ 3 次更新（`per_phase_updates`） | 超预算的实验直接拒绝，不"先跑再看" |
| tokens | 120000 | 单次决策 ≤ 20000（`max_tokens_per_decision`） | LLM 驱动时按此硬停；确定性驱动不消耗 |
| updates | 40 | 预留给 6 个 phase × 3 + 余量 | 同一 phase 的更新次数用满后只能 NOOP |

## 3. 实验前检查清单（`run_experiment` 会自动复核）

- [ ] 预算余额 ≥ 估算成本的 **1.5 倍**（为评估/回滚留余量）；
- [ ] `updates_left(phase) > 0`；
- [ ] playbook 在白名单，高危动作有 escalation 路径；
- [ ] 有可回滚的 champion 版本；
- [ ] 假设可证伪（有明确的拒绝条件，如"probe 增益 < 0.5pt 即失败"）。

## 4. 停止条件（满足任一即收手，转 NOOP）

- 连续 2 次实验门禁 `reject`（同一诊断类型）→ 判定该类型暂不可解，等待新证据；
- `labels_left < 2 × probe_labels` → 停止消耗标签，保留下轮监测预算；
- `tokens_left < 0.3 × tokens_total` → LLM 驱动降级为确定性；
- `updates_used ≥ updates_total` 或当前 phase 次数用满；
- 连续失败 ≥ `max_consecutive_failures`(3) → 触发收敛/收手；
- kill-switch 文件存在 → 立即停止一切更新（`run_experiment`/`deploy` 被拒）。

## 5. 反例

- ❌ **一个窗口内跑 3 个候选**：3 倍成本、无法归因，违反"一次一个变量"。
- ❌ **拿全部 labels 做一次全量微调**（如 220 条全用）：监测/评估预算归零，后续漂移无法
  及时感知，属于"实验设计事故"。
- ❌ **不记录 seed / 数据切片**：结果不可复现，审计直接失败。
- ❌ **把估算成本当实际成本**：必须用 `ExperimentResult.cost` 实测值回填
  `cost_actual`，否则成本-增益表失真。
- ❌ **实验失败不记录**：失败实验同样要 `finish_run(status="failed")` 并写原因，
  否则"全部实验完整记录"不成立。

## 6. 单位增益核算（写进每轮 summary）

```
gain_per_compute = Δprobe_macro_f1 / max(1e-9, cost_actual.compute_units)
gain_per_label   = Δprobe_macro_f1 / max(1, cost_actual.labels)
gain_per_token   = Δprobe_macro_f1 / max(1, cost_actual.tokens)
```

策略层（`Planner.update_strategy`）用同一口径更新先验；Harness 只需保证
`cost_actual` 与 `Δprobe` 都写进记录，`scripts/gen_record_book.py` 会自动汇总排名。
