# 实验优化与预算调度（Playbooks + Planner / 策略层自改进）

> 模块：`src/engine/playbooks.py`、`src/engine/planner.py`；接口契约见 `docs/03` §4.3–4.4。
> 本文回答三个问题：**有哪些动作、每个动作的真实恢复数字是多少、标签/算力预算怎么在
> "监测—诊断—实验—评估"之间分配**，以及"策略层自改进"如何被记录与验证。

---

## 1. 成本模型与统一实验协议

### 1.1 成本定义（与 `src/core/spec.py::Cost` 一致）

$$
\text{compute\_units}=\frac{\text{sample\_updates}}{\text{base\_compute\_unit}(=4000)},
\quad \text{labels}=\text{新购标签数},\quad
\text{tokens}=\text{LLM token}
$$

- `sample_updates = Σ over batches (batch size)`（`MLP.fit/fit_head` 返回），
  即"在基座训练集上完成 1 个 epoch 的样本更新量"=1 unit；
- 基座训练不计入适应成本（所有方法同样付出），部署后的每次更新都计入；
- 一次实验的 `Cost` 只报告"本实验新增"的标签/算力；**标签由 oracle 直接扣预算**
  （`SyntheticOracle.query` 内部 `BudgetState.charge`），引擎不重复扣，避免双记账。

### 1.2 统一实验协议（为什么这样设计）

每次候选实验分两段标签：

1. **评估留出集** `labels_eval` 条：从当前窗口购买，**在训练中绝不使用**；
   候选模型与现任 champion 在同一批标签上计算 `probe_macro_f1 / class_recall_min / ECE`
   → 门禁比较是**同分布、同批次、配对**的，消除"用不同标签比较"的偏差；
2. **训练集**：预算约束下取 `n_train = min(配置 labels, 剩余−预留−eval)`，
   与评估集 id 不相交（`BudgetedLabeler.acquire(exclude_ids=eval_ids)`）。

所有 playbook 的 `ExperimentResult.metrics` 至少包含：
`probe_macro_f1`、`baseline_probe_macro_f1`（同批留出集上的 champion 指标）、
`pred_stability`（与 champion 在无标签窗口上的预测一致率）、`class_recall_min`、
`ece`、`cost`、`labels`、`compute_units`。**门禁优先读 `baseline_probe_*`**，这一点是
"门禁不被探针噪声击穿"的关键（见 docs/06 §1）。

### 1.3 标签缓存（同一 id 只付费一次）

`BudgetedLabeler` 全局缓存 `id → (y, x)`，monitor 探针、diagnosis 探针、playbook 的
评估/训练标签共享同一缓存（缓存挂在 oracle 对象上，`get_labeler()` 懒加载）。
实测收益：主配置 S7 seed7 的 10 次候选实验中，多数评估标签来自缓存，
每次实验实际新购标签仅 0–16 条（`ExperimentResult.cost.labels`）。

## 2. Playbook 动作库（9 个，全部真实可跑）

| name | 层 | 风险 | 标签 | 算力 | 核心算法 |
|---|---|---|---|---|---|
| `NOOP` | model | low | 0 | 0 | 不更新，仅记录 |
| `RECALIBRATE_AFFINE` | model | low | 0 | 0 | **测试时自适应归一化（TTA）**：`adaptive=True`，推理时用当前 batch 统计量仿射对齐回源域（不改权重、不改 scaler、可跨窗口泛化） |
| `PRIOR_CORRECTION` | model | low | 0 | 0 | BBSE/EM 估计类别先验 + logits 先验校正（`b_last += strength·log(prior_hat)/T`） |
| `LAST_LAYER_FT` | model | low | 少 | 少 | 冻结隐藏层，`fit_head` 只训练最后一层；已知类过滤；标签过少时回退 TTA |
| `FULL_FINETUNE_REPLAY` | model | medium | 中 | 中 | 全量微调 + 基座域回放缓冲（`replay_n` 从 `base_x/base_y` 采样），`refit_scaler` 可配 |
| `RETRAIN_MIXED` | model | medium | 多 | 多 | 从零在"回放+新标注"混合集重训（新 MLP） |
| `NOVEL_CLASS_EXTEND` | model | high | 多 | 多 | 检测新类 → `expand_model_classes` 扩展输出层 → 回放+新标签训练，新类权重放大 |
| `SHADOW_ONLY` | strategy | low | 继承子动作 | 继承 | 候选仅影子评估，不替换 champion（`run()` 返回 `model=None`，loop 记为未上线） |
| `ROLLBACK` | strategy | medium | 少 | 中 | 有注册表可用时回滚到上一稳定版本；否则用基座历史数据重训基座模型 |

**TTA 为什么作为首选零标签动作**：一次性把目标域 scaler 固化进模型版本，会与后续
工况切换/新故障窗口失配（集成期实测：固化 scaler 的版本在 S7 phase3 从 0.745 掉到
0.369）；TTA 每窗口用当前 batch 统计量自对齐，对"老化/旋转"这类仿射成分通用，
且零标签零算力。逐场景实测（零标签，仅推理变换，`results/diagnostics/adaptive_tta.json`）：

| 场景 | 静态 | TTA | 增益(pt) |
|---|---|---|---|
| S1_gradual_wear | 0.8209 | 0.9850 | **+16.41** |
| S2_sensor_gain | 0.9501 | 0.9801 | +3.01 |
| S3_condition_switch | 0.6443 | 0.8453 | **+20.10** |
| S4_novel_class | 0.7816 | 0.7765 | −0.51 |
| S5_repair_cycle | 0.9451 | 0.9858 | +4.08 |
| S6_label_shift | 0.9805 | 0.8631 | **−11.74**（门禁按同批留出标签拒绝，不需要特判） |
| S7_full_mix | 0.7014 | 0.8153 | **+11.39** |

> 注：S6 的负增益恰好说明"先验证再上线"的必要性：TTA 在标签先验漂移下会错配，
> 但门禁用同批留出标签一测就知道是负增益 → 拒绝。这是"策略层 + 门禁"分工的实证。

1. **零标签 TTA 是性价比之王**：S7 P02 +0.21、S3 P03 +0.51、S1 P04 +0.35，标签 16、算力 0。

3. **NOVEL_CLASS_EXTEND 是唯一能真正处理新故障的动作**：S4 +0.217、S7 P11 +0.297；

4. **回放缓冲的双刃剑**：S3 P03 上 `replay_n=0` 的纯新域微调可达 0.952，而回放 900 条

   的必要保险。综合取 `replay_n=900`（配置可调），并在 S7 闭环中由门禁兜底。
5. **RETRAIN_MIXED 在本基准不划算**：S3/S7 都在 0.57–0.82、算力 15 units，是 LAST_LAYER
   的 10 倍算力而恢复更差；保留它作为"反复漂移、需要彻底重学"的兜底选项。

> **"可恢复上界"参考**（`eval_bench.upper_bound()`）：用 600 条当前域标签 + 基座 2000 条
> 从零重训的离线强参考（注意：这是"强参考"而非严格上界，本系统的低成本动作在部分窗口
> 反而超过它，因为它的重训会引入回放冲突）。实测：S3 P03 参考 0.859（本系统
> LAST_LAYER 0.888）、S4 P03 参考 0.923（NOVEL 0.949）、S7 P11 参考 0.732
> （NOVEL 0.707 = 参考的 97%）、S1 P04 参考 0.941（TTA 0.984）、S7 P02 参考 0.925
> （TTA 0.992）。结论：在 60–150 标签 + 零/低算力约束下，系统恢复能力已与"大量标签
> 从零重训"的强参考相当甚至更好。

## 4. 预算调度 Planner 与策略层自改进（bandit）

### 4.1 候选生成（`Planner.propose`）

```
输入：diagnosis.recommended（kind 先验表）+ 策略表后验 + 预算/白名单
1. 对每个 recommended playbook：
   a. 白名单过滤（safety.allowed_playbooks）；
   b. library.plan_labels() 判定可行性（标签/算力不足 → 剔除）；
   c. estimate_cost() 生成 Candidate{playbook, est_cost, prior, why, feasible}；
2. score = w·prior + (1−w)·posterior_success + ucb_explore − cost_penalty·est.scalar
   （w = planner.prior_weight = 0.5；posterior 见 4.2；默认确定性 UCB，无随机数 → 可复现）
3. 预算压力：est.labels > max(48, 0.55×labels_left) 时 score×0.45；
   诊断置信度 <0.5 时，带标签动作（labels>40）score×0.30（证据不足先做零标签/NOOP）；
4. 取 top-max_candidates（默认 3）；保证至少保留一个"便宜低风险"候选；
5. order() 按 cheapest-first 排序（同成本按分数）→ 交给 Harness Driver 决策。
```

`Candidate = {"playbook", "est_cost": Cost, "prior": score, "why", "feasible"}`（契约字段
+ 可行性标记）。`prior` 被复用作"排序分"，因此 bandit/成本/置信度都会真实影响最终选择。

### 4.2 Bandit 后验（`(diagnosis_kind, playbook)` 粒度）

策略表每格维护：`n, successes, failures, ema_reward, ema_cost, sum_reward, sum_cost,
last_gain`。成功定义 = **门禁通过且增益 > 0**（策略层自改进的核心信号）：

$$
\hat p_{succ}=\frac{succ + \alpha\cdot prior}{n+\alpha}\quad(\alpha=\texttt{prior\_strength}=2),
\qquad
\text{ucb}=\texttt{ucb\_c}\sqrt{\frac{\ln(N_{total}+1)}{n+1}}
$$

`update_strategy(kind, playbook, reward, cost)` 原子写回策略表：
`successes/failures`、EMA 收益/成本、累计和、最近一次增益；`reward` 由 loop 用**实际
增益 − 成本惩罚**计算（门禁失败时为负）。策略表持久化到
`experiments/runs/<run_id>/strategy_policy.json`（按 run 隔离，避免跨 run 污染），
schema：

```json
{"schema": 1, "n_updates": 7, "table": {
  "condition_switch": {"RECALIBRATE_AFFINE": {"n": 6, "successes": 0, "failures": 6,
       "ema_reward": -0.0154, "ema_cost": 0.291, "last_gain": -0.0164, ...}},
  "noise_inflate": {"RECALIBRATE_AFFINE": {"n": 4, "successes": 0, ...}}},
 "events": [{"kind": "condition_switch", "playbook": "RECALIBRATE_AFFINE",
             "reward": -0.016, "success": false}, ...]}
```

**实测证据（S7 seed7 集成 run）**：第 13 窗口 `noise_inflate → RECALIBRATE_AFFINE`
门禁通过（TTA 部署，收益为正）；t=17 起同一 `(condition_switch, RECALIBRATE_AFFINE)`
连续 6 次失败被记录（`n=6, successes=0`）。后验与 UCB 会把这些负经验计入下一轮打分
（`posterior_success` 从 0.5 降到 0.125），重跑/长流中该动作会被其它动作替换。
**这是"策略层自改进"的可审计证据**：策略表不是静态先验，而是由真实增益/成本回写的
状态；`planner.strategy_summary()` 直接把每格后验导出进结果 JSON。

### 4.3 预算分配（实测，S7 260 标签预算）

| 项 | 设计策略 | S7 seed7 实测（冻结版） |
|---|---|---|
| monitor 探针 | 预留 ≥60% 预算；控制探针每 3 窗口 ≤4 条；可疑时每 2 窗口 | ~80 条（20 次探针） |
| diagnosis 探针 | 只在"探针准确率下降/PH/novelty"时购买；单次 ≤min(20, 剩余/6)，全局 ≤32 | ~40–60 条（3–4 次） |
| playbook 标签 | 剩余预算内按 `labels/labels_eval/min_train/max_labels` 裁剪；为后续窗口预留 8 条 | ~90–120 条 |
| 结果 | `labels_used ≤ labels_total`（硬门） | **212 / 260**，compute 0，tokens 0 |

关键经验：**先零标签后带标签**。TTA 部署一次即可拿到 S7 +11pt 的大部分收益，
带标签动作只在"零标签动作无法解释漂移"（novel/label_shift）或门禁证明 TTA 不够时使用。
预算不足时优先 NOOP（不用小动作把预算碎片化），这条规则由
`planner` 的成本惩罚 + 置信度降权 + `playbooks.reserve_labels` 共同实现。

## 6. 局限与后续工作

1. **重复实验**：TTA 已上线后，同一 `(kind, RECALIBRATE_AFFINE)` 仍可能被 driver
   选中并重复花费评估标签（实测 6 次失败）。已写入策略表负经验，但"候选与 champion
   等价时直接跳过"还需要 registry lineage 与 candidate 的哈希比对（下一步）。
2. **NOVEL 的标签效率**：NOVEL_CLASS_EXTEND 仍要 ~100–160 标签；在 260 总量下只能做
   1 次，S7 的 P5/P6/P10/P11 新故障阶段因此只能部分覆盖。**"新类发现 → 主动采样"
   （active learning）** 是下一步的性价比最高方向。
3. **回放比例**：`replay_n` 对旋转类漂移是负资产、对遗忘是正资产，当前是全局固定值；
   理想做法是按诊断 kind 动态设置（condition_switch→小回放，repair→大回放），
   已在配置里预留 `replay_new_ratio` 等参数。
4. **成本口径**：本系统的 `compute_units=0`（适应动作都是零训练）在"单位增益/算力"
   上非常有利，但真实部署还需计入推理成本（见 docs/11）；本轮已把推理次数量化到
   `Decision.cost` 的统计中。
