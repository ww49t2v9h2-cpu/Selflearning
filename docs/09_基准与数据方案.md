## 1. 设计目标与三层数据方案

赛题要求"在无标签漂移流上自动完成 监测→诊断→实验→上线→回滚 闭环"，而校赛阶段
**没有官方数据包**。数据层因此分三层，覆盖"可控实验—真实数据验证—官方接入"：

| 层 | 数据 | 用途 | 优点 | 局限 |
|---|---|---|---|---|
| L1 合成漂移基准 | `src/data/synth.py` 的 S1–S7 | 主实验、消融、难度标定、门禁阈值校准 | 漂移机制可控可归因、可复现、可无限生成 | 世界是"造的"，非真实传感器 |
| L2 公开真实数据 | UCI AI4I 2020（CC BY 4.0） | 补充验证：适配层/闭环在真实工业数据上可跑通 | 真实工业机理、真实类不平衡 | 只有 1 个数据集、故障率 3.48% 噪声大 |
| L3 官方数据包 | `data/official/`（校赛后再发） | 正式评测 | 官方口径 | 格式/漂移强度未知，仅能给 adapter + 风险预案 |

设计原则（三条硬约束）：
1. **同一 `Benchmark` 契约**：三层数据最终都产出 `src/core/spec.py`/`synth.py` 冻结的
   `Benchmark`，引擎/Harness/闭环代码零改动切换数据源（`benchmark.adapter` 配置项）；
2. **标签物理隔离**：部署流 chunk 无标签；visible 标签只经 `LabelOracle` 按预算发放；
   hidden 标签只进 `Benchmark.hidden_by_chunk`，由 evaluator 消费，不进入系统快照；
3. **可复现**：所有随机性显式 seed；`WORLD_SEED` 固定"物理世界"；产物落盘含配置快照。

## 2. 数据层架构

```
                     ┌──────────────────────────────────────────────┐
                     │            Benchmark（冻结契约）               │
                     │ base_x/base_y  val_x/val_y                    │
                     │ chunks:[StreamChunk]  visible_y(仅 oracle)     │
                     │ hidden_by_chunk(仅 evaluator)                  │
                     └──────────────▲───────────────────────────────┘
                                    │ DatasetAdapter.load(root, cfg)
        ┌───────────────────────────┼─────────────────────────────┐
        │                           │                             │
 ┌──────┴───────┐          ┌────────┴────────┐          ┌─────────┴────────┐
 │ SynthAdapter │          │  AI4I (公开)     │          │ OfficialAdapter  │
 │ synth.py     │          │ public_ai4i.py  │          │ adapter.py       │
 │ S1–S7        │          │ 22 窗口/4 阶段   │          │ data/official/   │
 └──────────────┘          └─────────────────┘          └──────────────────┘
        │                                                          │
        └──────────── SyntheticOracle / VisibleLabelOracle ────────┘
                    （按 labels_total 预算发放 visible 标签并记账 Cost）
```

关键实现：
- `make_benchmark(cfg, seed)`：合成基准（S1–S7 由 `cfg["benchmark"]["scenario"]` 选择）；
- `DatasetAdapter` 协议 + `OfficialAdapter`：官方数据包加载/校验/清晰错误提示；
- `make_ai4i_benchmark(cfg, seed)`：AI4I 公开数据转 Benchmark；
- `load_benchmark(cfg, seed, root)`：按 `cfg["benchmark"]["adapter"]`（synth|official|ai4i）选择；
- `SyntheticOracle` / `VisibleLabelOracle`：`LabelOracle` 协议实现，去重 + 预算硬截断 + 记账。

基准规模（默认配置 `phase_n=1800, chunk_size=200, hidden_ratio=0.34`）：
- S1–S6：6 阶段 **30 窗口**（每阶段 5 窗口，每窗口 200 样本，hidden≈123/窗口）；
- S7：12 阶段 **60 窗口**；
- base 训练集 4000（4 类均衡）、验证集 1000；评测类别 5（含 novel 类）。

## 3. 合成基准的世界模型与漂移机制

### 3.1 潜变量 → 观测（工业故障诊断的"预提取特征"类比）

- **潜变量 `z ∈ R^6`**：6 个特征频带能量，对应轴承特征频率 BPFO/BPFI/BSF/FTF 等；
- **类别指纹**（`CLASS_PROFILES`，4 基础类 + 1 novel）：正常类各频带低能量；
  内圈/外圈/滚动体故障分别在频带 1/2/3 出现尖峰；novel 为多频带复合能量；
- **观测模型** `x = z @ W^T`：`W`（48×6）= 8 路传感器敏感度矩阵 `A` × 6 种统计量混合
  `C`，模拟振动/电流/温度/声发射传感器的频带响应差异；叠加各传感器不同噪声；
- 观测维度 48 = 8 路传感器 × 6 种时域/频域统计量，与官方"预提取特征"同形。

### 3.2 六类漂移机制（与赛题"工业场景漂移"一一对应）

| # | 机制 | 生成方式（潜空间/观测空间） | 可恢复手段 | 对应场景 |
|---|---|---|---|---|
| M1 | 渐变磨损 | `z += τ·wear_dir`（τ 随阶段递增，共模协变量漂移） | 带标签微调/重训、回放 | S1、S5、S7 |
| M2 | 传感器增益老化 | `x = x·(1+γ·g) + γ·0.12·g`，噪声 `×(1+0.35γ+ν)`（标签保持的逐特征仿射变换） | **无标签仿射校准**；带标签重训 | S2、S5、S7 |
| M3 | 工况切换 | 潜空间旋转+平移 `z = z@R_c^T + o_c`（类条件关系改变=概念漂移） | 带标签微调/重训；回放 | S3、S7 |
| M4 | 未知故障模式 | 新类别样本占比 `novel_frac` 逐步上升（评测类别 5，模型原输出 4） | 新类检测 + 类别扩展 + 标注 | S4、S7 |
| M5 | 标签先验漂移 | 仅 `y` 抽样概率变化，特征条件分布不变（`P(x|y)` 不变） | 先验校正（EM/BBSE）；**不应重训伤模型** | S6 |
| M6 | 维修复位 | 增益/磨损参数回到基线（分布突然恢复） | 回滚/记忆（replay）；避免错误适应 | S5、S7 |

### 3.3 场景剧本（S1–S7）

| 场景 | 阶段数 | 主要机制 | 设计意图（考什么） | 期望系统行为 |
|---|---|---|---|---|
| **S1** 渐变磨损 | 6 | M1：wear 0→1.10 单调累积 | 渐缓退化是否被监测发现；周期重训是否跟得上 | 早发现、低频更新、避免过度反应 |
| **S2** 传感器增益老化 | 6 | M2：gain 0→1.25 + 噪声膨胀 | 无标签协变量漂移能否用**零标定**仿射校准修复 | 优先 RECALIBRATE_AFFINE，省标注/算力 |
| **S3** 工况切换 | 6 | M3：A→B→C→A（旋转+平移） | 概念漂移需要带标签适应；切回后能否回滚/复用 | 少量标注微调；回切时 ROLLBACK/重载 |
| **S4** 未知故障模式 | 6 | M4：novel_frac 0.05→0.25→0.02 | 新类检测与类别扩展；结构漂移下 macro-F1 惩罚 | 检测新类→NOVEL_CLASS_EXTEND |
| **S5** 维修复位 | 6 | M2+M1 → M6 复位 → M1 二次磨损 | 分布恢复后的"回滚/记忆"；避免把修复后当新漂移 | 检测 repair、回滚 champion、保留回放 |
| **S6** 标签先验漂移 | 6 | M5：均衡→单类主导→均衡 | **良性漂移**：特征不变，不应重训/伤模型 | 仅先验校正或 NOOP，记录证据 |
| **S7** 综合漂移（主线） | 12 | M1~M6 混合：磨损+老化→工况切换→新类→维修复位→二次漂移 | 策略选择、预算分配、门禁与回滚的综合考察 | 诊断→选择最划算 playbook→门禁→必要时回滚 |

S7 阶段剧本（12 段）：基线 → 渐变磨损 → 传感器老化 → 工况切换B → 工况B稳定 →
新故障出现 → 新故障增多 → 维修复位 → 复位后漂移 → 再次老化 → 新故障再临 → 深度漂移。

## 4. 难度标定（v1.1，2026-11）

### 4.1 为什么需要标定（初版问题，实测）

初版 `synth.py` 在 3 seeds 下的静态基线（hidden macro-F1）暴露两个问题：

| 问题 | 初版实测 | 后果 |
|---|---|---|
| 跨 seed 难度方差过大 | S3 各 seed 均值 0.31 / 0.65 / 0.50；S7 均值 0.64 / 0.81 / 0.73 | 3 seeds 平均无统计意义，多种子实验不可比 |
| S1 退化不足 | 深度磨损阶段静态 F1 仍 0.91–0.93（几乎不退化） | "渐变磨损"场景考不出监测/更新价值 |
| S2 仿射可恢复性不足 | 极端老化 static 0.80，仿射校准仅 +4.5 点（噪声膨胀淹没仿射信号） | 无法体现"零标注适应"的价值 |

根因：① 初版每次 seed 重新生成"物理世界"（传感器混合矩阵+随机工况旋转矩阵），
随机正交阵与类判别方向的夹角随机，导致 S3/S7 难度剧烈波动；② 磨损潜空间位移方向
幅度仅为类间距离 ~0.2 倍；③ 增益老化耦合的噪声膨胀系数 1.2 过大。

### 4.2 标定改动（接口冻结，仅内部实现）

| 改动 | 内容 | 效果 |
|---|---|---|
| **固定世界** | 新增 `WORLD_SEED=20261116`：传感器混合矩阵 A/C/W、噪声尺度、增益敏感度、工况旋转/偏置只用该种子生成；`seed` 只控制数据采样、hidden/visible 划分与模型初始化 | 跨 seed 只反映统计波动，难度可比；同一 seed 仍完全可复现 |
| **磨损幅度** | `WEAR_DIR` 幅度 ×2.5（`[0.625,0.25,0.45,0.55,0.375,0.25]`） | S1 深度磨损 static 0.93→0.62（单调下降） |
| **增益噪声耦合** | `GAIN_NOISE_COUPLING` 1.2→0.35 | S2 以"可仿射恢复"为主（极端老化 static 0.882→仿射 0.959） |
| 场景参数 | 仅 S5 P05 二次磨损沿用原参数；S1/S2/S3/S4/S6/S7 剧本保持不变 | 阶段名/阶段数/接口不变 |

> 说明：S3 的"工况C"（潜空间旋转更强）静态 F1（0.31–0.34）显著低于"工况B"（0.62），
> 这是**刻意保留的不同严重度**——对应真实工厂不同负载谱，可同时考察中度/重度概念漂移。

### 4.4 跨 seed 方差与确定性

- **确定性**：同一 seed 连续两次运行，`base_x/visible_y/chunks.x/hidden_by_chunk`
  逐元素相等（`tests/test_data.py::test_determinism_same_seed`）；基线套件两次全量运行的
  数字完全一致（人工核对）。
- **跨 seed 方差**：固定世界后，各场景跨 seed 的 phase-mean F1 标准差 ≤0.03
  （S1 ±0.006、S2 ±0.002、S3 ±0.005、S4 ±0.002、S5 ±0.004、S6 ±0.003、S7 ±0.011，
  见 `results/baselines/table.md` 表 1），3 seeds 平均具备统计意义。
- **seed 语义**：`seed` 控制数据采样（标签抽样/观测噪声/hidden-visible 划分/逐阶段抽样）
  与模型初始化；"物理世界"固定。这使"多种子方差"≈ 统计波动，而不是"换了一个世界"。

## 5. 基线实验套件（B0 / B1 / B2）

### 5.1 定义（`scripts/baseline_suite.py`）

| 基线 | 定义 | 标注 | 适应算力 | 角色 |
|---|---|---|---|---|
| **B0 static** | base 模型部署后**不更新** | 0 | 0 | "不进化"下界 |
| **B1 periodic** | 每 3 个窗口用 60 条新标注（经 oracle）累积，与 base 训练集从零**全量重训** | 600（S7:1200） | 433（S7:926） | "勤重训但不做实验设计" |
| **B2 oracle** | 每个漂移阶段用 600 条标注（均匀覆盖该阶段各窗口），与 base 合并从零重训 | 3600（S7:7200） | 276（S7:552） | **上界**（预算充足） |
| 自进化系统（Lead 实现） | 监测→诊断→playbook 实验→门禁→上线/回滚，受 `labels_total=260`、`compute_total=260` 硬预算 | ≤260 | ≤260 | 主方法 |

统一口径：隐藏测试逐窗口 macro-F1/accuracy，按阶段聚合，跨 3 seeds（7/17/27）平均；
标注/算力全部通过 `Cost` 记账（`labels`、`compute_units = sample_updates/base_compute_unit`、
`compute_seconds`），写入 `results/baselines/*.json` 供 Pareto 分析。

### 5.4 关键洞见（对自进化方法的设计启示）

1. **"不更新"在概念漂移下会崩**：S3 静态 0.644、S7 0.701，说明监测-适应闭环有明确价值。
2. **标注预算的边际收益递减**：S7 上 B1 用 1200 标注 +0.096，B2 用 7200 标注 +0.211
   —— 自进化系统应以 **≤260 标注**逼近 >0.80 作为目标（Lead 主实验）。
3. **B1 的算力反而高于 B2**（S7：926 vs 552）：频繁全量重训很贵；"少而准的更新"
   （先诊断再选 playbook）是成本效率关键——这正是 `Planner` 与门禁要证明的。
4. **S2 是"零标注适应"的靶场**：见 §5.5，无标签仿射校准（0 标注、0 适应算力）在极端老化
   阶段 0.882→0.959，**超过 B1（0.906）与 B2（0.928）**；系统应优先选
   `RECALIBRATE_AFFINE` 而非无脑重训。这是"先诊断、再花预算"最有力的证据。
5. **S6 是"不该动作"的靶场**：静态 0.981、B1/B2 均 0.98±，重训毫无收益；
   优秀系统应检测到"标签先验漂移（良性）"后 NOOP/仅先验校正，把预算省给真漂移。
6. **S5/S7 的维修复位**：分布突然恢复（S7 P7 静态回到 0.987）时，若继续用"漂移后"的
   champion 会退化；需要回滚+回放记忆（Watchdog/Registry 的用武之地）。

### 5.5 S2 零标注仿射校准对比（体现"诊断驱动适应"的价值）

hidden macro-F1，3 seeds（7/17/27）均值±标准差；"仿射"= 用当前窗口无标签特征估计目标域 scaler 后 `align_predict_proba`
（`RECALIBRATE_AFFINE` 的核心原语，0 标注、0 参数更新算力）。
复现命令：`$PY scripts/analyze_affine_s2.py`；原始数字：`results/diagnostics/s2_affine.json`。

| 阶段 | B0 static | 仿射校准（0 标注） | B1 periodic（600 标注累计） | B2 oracle（3600 标注） |
|---|---|---|---|---|
| P0 基线 | 0.988±0.001 | 0.984±0.002 | 0.986 | 0.988 |
| P1 轻微增益 | 0.982±0.005 | 0.988±0.002 | 0.983 | 0.987 |
| P2 中度增益 | 0.975±0.011 | 0.988±0.007 | 0.977 | 0.978 |
| P3 重度增益 | 0.959±0.005 | 0.988±0.002 | 0.967 | 0.975 |
| P4 增益+噪声 | 0.914±0.009 | 0.975±0.005 | 0.921 | 0.944 |
| P5 极端老化 | 0.882±0.010 | **0.959±0.006** | 0.906 | 0.928 |

> 结论：S2 上"0 标注的仿射校准"在漂移后期全面优于"600~3600 标注的全量重训"。
> 说明**先诊断漂移类型再选最便宜的 playbook** 是预算约束下的最优策略。

### 6.2 工况设计依据（用实测数据而非 Type 直觉）

- `Type`(L/M/H) 对 5 个传感器分布几乎无影响（各 Type 均值差 <1%），只轻微影响故障先验 → **不用 Type 做特征**；
- 真正的协变量漂移在**转速-扭矩-功率**方向：低转速(<1450rpm)重载工况故障率 **7.9%**、
  中转速 0.7%、高转速(≥1600) 1.5%；低转速段扭矩均值 49.7Nm vs 高转速 29.5Nm；
- 刀具磨损是渐变漂移主变量：低转速工况磨损≥200min 段故障率升到 **31%**。

### 6.3 转换剧本与结果

特征 11 维（5 传感器 + 7 个物理工程特征，见 README 字段映射）；标签 2 类（正常/故障）；
base = 重载低转速 & 磨损<80min；4 个阶段；22 个窗口（200 样本/窗口，hidden 34%）。

| 阶段 | B0 static | B1 periodic | B2 oracle |
|---|---|---|---|
| P0 基线延续(重载,磨损80-140) | 0.707±0.117 | 0.656 | 0.775 |
| P1 深度磨损(重载,磨损≥140) | 0.473±0.023 | 0.565 | 0.734 |
| P2 工况切换A(中转速,磨损≥80) | 0.426±0.053 | 0.619 | 0.548 |
| P3 工况切换C(高转速,全磨损) | 0.496±0.006 | 0.600 | 0.619 |

| 标注数 | 0 | 480 | 2400 |

> 补充：真实数据**闭环**结果（3 seeds 7/17/27）：自进化系统流式 F1 **0.5527** vs 同 run 静态 **0.4964**
> （**+5.63pt**，`results/real/`、`results/SUMMARY.json` 的 groups.real）；数据适配层切换零改动。

结论：① 适配层/基线/闭环代码在真实数据上**零改动可运行**；
② 静态模型在真实漂移下故障召回/误报显著恶化（accuracy 也会掉），周期重训/oracle 能恢复；
③ 真实数据的类不平衡使 macro-F1 对稀有类采样敏感（每阶段 hidden 故障样本仅 7–54 条），
波动大于合成基准，**因此 AI4I 只作补充验证，不进入 S1–S7 难度主表与 Pareto 主图**。

### 6.4 局限与使用建议

- 单数据集、2 类、极端不平衡（3.48%）：适合验证"接口/闭环可运行"与"真实漂移存在"，
  不适合比较不同方法的精细差异；
- 评测建议同时报告 accuracy 与故障类 recall（macro-F1 在无故障窗口上会退化为
  "仅正常类 F1"，存在结构性偏差）；
- 后续可补充：NASA C-MAPSS 涡扇发动机退化、Pronostia 轴承退化等公开数据（同样 CC/开放许可），
  扩大真实数据覆盖面（列入后续工作）。

## 8. 与官方数据包的差距与风险

详见 `docs/15_与官方数据包对接.md`。要点：
