## 1 三档开场陈述

### 1.1 30 秒版（电梯陈述，背熟）

工业模型上线后会因磨损、老化、工况切换持续失准。我们做的是**智训引擎**：在无标签漂移流上自动完成
「监视 → 诊断 → 实验 → 上线 → 回滚」闭环，每一步都记账、可审计、可回滚。核心一句话：
**诊断决定最小充分动作——不是所有漂移都值得重训。**

### 1.2 2 分钟版（推荐默认开场）

各位评委好，我们的项目是「智训引擎」——工业模型自进化系统。

赛题给了一个很硬的矛盾：工业数据**无标签、还在持续漂移**；但预算只有三样——**算力、标注、Token**，
而且这三样直接进客观分分母。所以问题不是"怎么把模型训得更准"，而是**"什么时候值得动、动哪一步、花多少钱"**。

我们的回答是三个判断：
第一，**漂移分类型、动作分阶梯**。轴承磨损要微调；传感器老化是仿射变换，零标签就能校准；
工况切换要带标签微调；新故障要扩类别；维修复位要回滚。我们把 9 个动作做成成本阶梯，**NOOP 也是合法动作**。
第二，**LLM 不进高频回路**。每窗口的数值决策用确定性策略 + 在线 bandit，零 token、可复现；
LLM 只在每漂移一次的归因解释、实验设计、报告生成里出现。
第三，**受控 RSI**。递归只允许发生在"模型版本滚动"和"策略先验更新"两处，边界是白名单、预算硬门、熔断、审计链。

系统是五阶段状态机，一条命令跑完，所有决策进 sha256 哈希链审计日志；
实验记录本地 SQLite + SwanLab 兼容三模式。

结果上：**S7 综合漂移，静态 0.7014 → 自进化 0.8000，+9.86 个百分点**，只花 **196 条标注、0 适应算力**、等效成本 3.92；
七场景平均 **+5.01pt**；真实数据 AI4I 同套代码换 adapter 后闭环 **+5.63pt**；验收 A1–A7 全部通过。
对比一下：周期重训要 **1200 条标注 + 926 units** 才 0.7973，Oracle 上界要 7200 条标注——
**这个赛题的胜负手是单位增益成本，不是绝对精度。**

### 1.3 5 分钟版（完整叙事，用于评委让你"展开讲讲"）

**第 1 分钟｜问题**：工业现场不是 Kaggle 榜单。模型上线后，轴承会磨损、刀具会钝化、传感器会老化、
工况会切换、还会冒出新故障。数据在漂、标签没有，预算还卡死。赛题要求五阶段闭环无人干预跑完：
监测→诊断→实验优化→评估上线→回滚。所以我们要解决的是一个**带成本约束的决策问题**，不是单点算法。

**第 2 分钟｜路线选择**：我们对比了三条路。R1 纯微调：便宜但笨，每类漂移都全量更新，
传感器老化这种零标签可解的也烧标注，而且没有归因、策略不学习、开集新故障处理不了。
R2 纯 LLM Agent：聪明但贵——按 PyTRi0 定价一次 4k+600 token 决策约 ¥0.049，60 个窗口×3–5 次就是 ¥9–15/run，
token 还直接进客观分分母，且高频数值决策不可复现、封闭评测里 LLM 格式失败就事故。
我们选 R3 混合双层：**高频数值决策交给确定性策略+bandit，中频实验交给 9 个 playbook，
低频开放式决策才用 LLM**。Harness 完整保留（12 工具、6 技能、双驱动），只是默认不烧 token；
LLM 驱动用 mock provider 跑通了完整闭环（S7 +7.84pt、108,612 mock token 估算），协议与计量链路已验证。

**第 3 分钟｜系统**：闭环每个窗口先做无标签监测（MMD、逐特征 KS、预测熵/边际、Page-Hinkley、novelty），
每 2 个窗口花 6 条标注做准确率探针；触发后诊断 8 类漂移，关键创新是用预算内标签**实测"仿射可恢复性"**：
对齐目标域统计量后探针准确率显著回升，判 covariate_affine，零标签校准；不回升才升级到带标签微调。
然后规划器按"先验×成本"cheapest-first 出候选，实验、门禁（增益/类召回/校准/成本）通过才上线，
上线后 watchdog 连续退化自动回滚。所有决策进 Decision 和哈希链审计。

**第 4 分钟｜证据**：S7 主实验 3 seeds：静态 **0.7014 → 0.8000（+9.86pt）**，逐 seed +8.77 / +9.71 / +11.11；
成本只有 **196 条标注 / 0 units / 3.92**，单位增益成本 **0.40**，而 B1 周期重训 99.12、B2 Oracle 33.09。
七场景平均 +5.01pt：S3 工况切换 +19.00pt 最亮眼，S1 +5.17pt，S6 负对照 0.00（不浪费预算）。
消融给出因果：**关诊断 → +0.00、关零标签 TTA → −0.56**，说明"诊断 + 最小充分动作"是主收益来源。
决策质量也量化了：覆盖率 68.9%、兑现率 12.2%、门禁拒绝"增益不足"候选 70.3%。

**第 5 分钟｜边界与价值**：我们主动说边界：校赛没有官方数据包，主实验在可控合成漂移基准上，
但隐藏测试与标注预算约束在仿真里**真实生效**（0.34 隐藏隔离 + oracle 预算）；真实数据 AI4I 上同套系统只换 adapter 即闭环 +5.63pt。
S4 开集新类 0.00、S7 中后段预算耗尽后退化 NOOP——这是预算边界内的正确保守行为，不是隐藏。
LLM 只有 mock 额度、没有真实 PyTRi0 对比，也写在局限页。企业赛拿到官方数据后只换 `DatasetAdapter`。
这就是我们的交付：**一个可运行、可复现、可审计、预算受控的模型自进化系统。**

## 3 31 题问答库（每题回答 ≤150 字；**加粗**是必须说出的信息）

### A 组：技术路线类

#### Q1 为什么不用纯微调（Fine-tune-only）？

**回答**：纯微调**每类漂移都全量更新**，传感器老化这类零标签可解的也要烧标注；它无归因、策略不学习、
同类漂移重复犯错，开集新故障还输不出新类。我们把它保留为基线 B1：S7 用 **1200 条标注 / 926 units 只拿 +9.6pt**，
成本效率不可接受。

**证据位置**：`docs/02 §2 R1`；`results/baselines/table.md` 表 1（B1 行）；对比代码 `scripts/baseline_suite.py`。

**追问预案**：若问"B1 也挺好"→ B1 在 S7 是 0.7973 且成本 99.12 scalar/百分点，Ours 是 0.40；B1 在 S6 甚至 −0.1pt。

#### Q2 为什么不用纯 LLM Agent？你们到底用没用大模型？

**回答**：纯 LLM 每窗口 3–5 次调用、单次约 ¥0.049，60 窗口 ¥9–15/run，token 进成本分母且不可复现。LLM 只做低频归因/实验设计/报告（估算 <¥0.3/run）；LLM 驱动（mock）已跑通闭环验证协议（S7 +7.84pt），Harness 12 工具+6 技能+双驱动完整。

**证据位置**：`docs/02 §2 R2/§3.3`；`src/harness/agent.py`；`src/providers/`；`results/SUMMARY.json → groups.route-mockllm`；`docs/07`。

#### Q3 递归自改进（RSI）会不会失控、越改越差？

**回答**：递归只发生在模型版本滚动与策略层数值先验两处。策略层不能改代码/门禁/预算、不联网、不越白名单；高风险动作留升级记录；预算耗尽/连续失败/STOP/审计失败即熔断；每次 promote/rollback 写 Decision 与 sha256 哈希链，可 audit-verify 校验。

**证据位置**：`docs/02 §3.2/§7`；`src/engine/safety.py`；`src/loop.py` 安全护栏段；`docs/06`；`results/acceptance.json` A5/A6。

#### Q4 你们的创新点是什么？和普通域适应/MLOps 有什么不同？

**回答**：三点：①诊断可测——用预算内标签实测仿射可恢复性，归因从拍脑袋变可验证；②目标带成本分母——把「该不该更新」建模为单位增益成本，9 个动作是成本阶梯，NOOP 合法；③受控 RSI——模型版本与策略先验都可 diff、可回滚、可审计。差异是我们优化「花得值」。

**证据位置**：`docs/02 §3`；`docs/项目一页纸.md §2`；`src/engine/diagnosis.py`（仿射可恢复性实测）。

### B 组：实验与数字类

#### Q5 单位增益成本怎么算？平台口径和你们不一样怎么办？

**回答**：Gain=窗口平均(hidden F1−静态 F1)×100；Cost=1.0·compute+0.02·labels+1e-5·tokens。S7 实测 +9.86pt/3.92 → 单位增益成本 0.40（B1 99.12、B2 33.09）。平台口径未知，所以做三组权重敏感性 + Pareto 前沿。

**证据位置**：`docs/11 §1/§2/§4/§5`；`src/core/spec.py::Cost`；`src/core/config.py::cost_model`；`results/SUMMARY.json → groups.main.gain_per_cost_mean`。

#### Q6 合成数据凭什么代表工业？是不是"自娱自乐"？

**回答**：合成流按赛题机制构造 48 维预提取特征流，静态基线实测失准：S7 从 0.988 退化到 0.444、S3 掉到 0.644。真实数据 AI4I 上同套系统只换 adapter 即闭环 **+5.63pt**（0.4964→0.5527），验证接口可迁移；差距与风险写 docs/09 §5。

**证据位置**：`src/data/synth.py`；`results/baselines/table.md` 表 2；`docs/09 §5/§6`；`results/SUMMARY.json → groups.real`。

#### Q7 隐藏测试流怎么防泄漏？怎么证明没在测试集上调参？

**回答**：生成数据时按 hidden_ratio=0.34 把每个窗口切成可见/隐藏两份，隐藏标签只在 HiddenEvaluator 可读的数组里，系统侧拿不到；系统只能经 LabelOracle 按预算取可见标签。决策只用无标签信号+探针标签，隐藏分数仅用于报告，loop.py 有注释。

**证据位置**：`src/data/synth.py` L201-215、L362-388；`src/core/spec.py` 模块文档串；`src/loop.py` L9、隐藏分数只用于报告；`docs/09`。

#### Q8 主实验 S7 到底提升了多少？

**回答**：静态 **0.7014 → 自进化 0.8000，+9.86pt**（3 seeds 均值；逐 seed +8.77/+9.71/+11.11），只用 **196 条标注 / 0 算力 / 成本 3.92**；B1 用 1200 条标注+926 units 才 0.7973。验收 A2 ✅（+8.77pt），恢复曲线见图 1。

### F 组：方法学与判据可信度（配套研究映射，Q21–Q22）

#### Q21 你们的门禁/监测也是自适应判据，凭什么说它不会自己坏？

**证据位置**：`notes/学习_dyn3三篇_与智训引擎的映射.md §3（Paper I/III）、§4 第 1–2 条`；`src/engine/monitor.py::_maybe_rebase`；`src/engine/gates.py`；`src/loop.py`（promote 后才 rebase）；`docs/06`。

**追问预案**：若问"那道防线落地了吗"→"双门不变量与方向指示是引擎侧加固项（见审阅意见 P1-16），我们明确说它是工程约束，不是已证明的安全保证。"

### G 组：相关工作与新颖性（2024–2026，详见 docs/16）

#### Q23 OpenAI/Google/Anthropic 都在做"自改进飞轮"，你们的差异是什么？

**回答**：他们做的是**模型/训练层**的自改进（OpenAI Tax AI 用专家反馈+生产轨迹+evals 6 周 25%→86%；
Anthropic《When AI builds itself》称 >80% 代码由 Claude 写、AAR 自动对齐研究超 28 人；Google AlphaEvolve 用评估器驱动进化搜索——以上均为**公司自述，未独立复现**）。
我们做**应用层、无标签工业漂移流**上的控制回路：漂移监测→诊断归因→预算化实验→门禁→回滚。
差异四点：无标签（无现成验证器，用探针标签构造临时验证器）、双层受控 RSI（模型 playbook 版本滚动+策略 bandit）、
预算受限实验分配、自动门禁与回滚。**不声称首创**，定位是"把自进化做成可运营、可审计的工业控制回路"。

#### Q24 2026 年已有 VaG/Bilevel/Gated 等"门禁式自进化"论文，你们还新在哪？

**回答**：承认它们（VaG 预提交门禁、Bilevel 机制级双层+门禁/回滚、Gated 评估器分离定理），
**门禁与回滚是合规底线、不是我们的创新**。我们的问题是这些工作没解决的：**无标签流上验证器从哪来**。
答案：用**预算内探针标签构造临时验证器**、用同批留出标签实测增益过门禁、并把"门禁拒收"与"参考域更新"
解耦（**双门不变量**），再叠加预算硬门与哈希链审计。证据：A2 关闭诊断→+0.00、A7 关闭 TTA→-0.56。

#### Q25 华为盘古/软通天璇已经有工业大模型和平台，你们的价值是什么？

**回答**：命题企业的公开材料覆盖"模型接入—微调—部署—行业本体—生产控制闭环"，但**没有"模型质量自身的闭环"**：
自动发现失准、自主实验、门禁上线、失败回滚。我们补这一环，且接口可对接既有基座（`DatasetAdapter` 接官方数据包、
LLM provider 可接盘古/天璇/PyTRi0）。表述上我们不做"填补空白"，只做"在既有基座之上补自动决策—门禁—回滚控制回路"；
验证的是**控制回路**（S1–S7 可控漂移单元测试 + AI4I 真实数据冒烟），不承诺产线绝对精度。

#### Q26 有文献说 TTA 收益被高估、会遗忘和累积伪标签误差，你们为什么还用 TTA？

**回答**：正是这些文献（延迟审计 arXiv:2610.12232、CTTA 综述 TMLR 2026）让我们**不把 TTA 当无条件收益**：
TTA 只是 9 个候选动作之一，必须用**同批留出标签实测增益**、过门禁才上线，否则 NOOP；上线后看门狗持续监控、异常回滚。
我们的 A7 消融（关闭 TTA → -0.56pt）说明它在 S7 上有真实贡献，但 S6 标签先验漂移上它会 -11pt 并被门禁拒绝——
**"诊断+门禁"才是设计，TTA 只是被管理的工具**。

#### Q27 配套研究 J1 说"无外来信道时自改进不可行/不可认证"，你们的系统怎么自洽？

**回答**：J1 分析的是**闭合自指回路**：残差由判据自己定义（`ρ=|y−wᵀx|` 里的 `y` 来自判据吸收的样本），
尺度 τ 与权重 w 被同一批残差更新，所以回返映射是自指的；J1 证明该映射类可含马蹄/正熵
（精确熵 `log(2+√3)`）、存在乘子 −32 的周期三（Sharkovsky/Li–Yorke），且一般情形不可判定
（Koiran/停机归约），**没有任何单阈值监控能判定参数是否在混沌区**，只有零熵充分证书可检验。
我们的系统**不是闭合自指**：外部分布信号（监测）、外部标注（LabelOracle 探针/训练标签，Anchor 信道）、
固定探针（只体检不学习，Probe 信道）、平台隐藏评测（隔离，不进决策）、预训练基座共同构成外部信道；
双门不变量（被门禁拒绝的样本不写参考域）+ 版本回滚 + 哈希链审计进一步切断自指污染。
所以 J1 的不可能性恰好是**我们预算化外部信道、并保留 NOOP/回滚**的理由：去掉外部标注与独立评估、
只让策略表用自己的预测发奖励，就会落入 J1 的混沌/两个终态失效。引用口径：配套研究（J1，未投稿）。

#### Q28 路线 A（大模型 Harness）和 B（持续微调）怎么选？会不会因为选 A/B 被扣分？

**回答**：官方速览视频明确：**"评分只看效果、成本与论证质量，不因路线选择加减分"**。我们选混合双层，
不是因为押注某条路线，而是因为单位增益成本与可审计性：模型层用最便宜的 TTA/校准兜底（零标签、0 算力），
只有探针证据足够才升级到带标签微调（B 线做法）；策略层用确定性 planner + 可选 LLM 做低频决策（A 线做法）。
证据：A2 关闭诊断 +0.00、A7 关闭 TTA −0.56、196 条标注/0 训练算力。若评审偏好纯 A 或纯 B，
配置层可切换（provider=deterministic/llm，playbook 白名单可裁剪），系统不绑定路线。

#### Q29 决赛换数据包-B（含脏数据），你们怎么准备抗干扰？

**回答**：新增 `RobustSanitizer`：非有限值（NaN/Inf）用干净训练集中位数填充，极端值按 0.1%/99.9% 分位截断，
统计量只来自干净训练集，loop 与隐藏评测共用同一清洗器，修复量写入运行记录。压力测试（S7 seed7，注入 NaN/异常值/整块传感器掉线）：
轻度脏数据 F1 **0.798**（相对干净仅 −0.34pt），重度 **0.704**（仍 +1.02pt vs 静态基线）；
**不清洗时 0.405/0.159，性能崩塌**。官方模板 `configs/official_template.json` 默认开启清洗。
拿到数据包-B 后会再确认时间戳错乱/重复采样/多源缺失的清洗规则；泛化余量靠 TTA + 探针门禁 + NOOP/回滚。

#### Q30 为什么不多采样/并行多跑几个模型，再让验证器挑最好的？

**回答**：配套研究 J2（未投稿）正好回答这个：①**覆盖率≠兑现**——8 样本 × 4 模型家族的实测里，
可达增益只有 0–3%（GSM8K）到 7–96%（MATH）被验证器兑现，兑现由"验证器拒绝什么"决定；
②**N=1 在计入调用成本时常是计算最优**，样本变便宜时才移到 2/4/8；③**串行与并行首次接受是同一
决策函数**（返回同一答案），但并行多花 5–8 倍调用。我们的系统因此**单候选、cheapest-first、串行、
NOOP 合法**，把预算花在**探针门禁的判别力**上（覆盖率 68.9% / 兑现率 12.2% / 拒绝坏候选 70.3%）；
多铺候选只会放大算力/标注/Token 成本且不改变决策函数，直接伤资源效率 5 分。我们把这一点做成了候选级操作点曲线：119 个候选上实际门禁放行率 17.6%、放行候选平均真实增益 +13.50pt、90.5% 达标；纯 probe 阈值在相近放行率下略差（86.4%、+12.89pt），说明门禁的硬条件在起作用（docs/10 §7）。

#### Q31 你们的判据（监测/门禁/看门狗）自己会不会坏掉？被慢慢带偏怎么办？

**回答**：会，而且**有方向**。配套研究 J3（criteriond，未投稿）把判据当有状态对象：同一带内攻击
r=0.99 下，滚动中位数尺度到"接受一切"（τ→2.85×10⁹）、EMA 到"拒绝一切"（τ→2.45×10³），
固定阈值两者皆不；宽门会爆炸且错误接受率 74.47%，**双门隔离**以 90.68% 隔离率恢复严格门质量。
我们的落地：①固定阈值 + 失效方向指示器（accept_all/reject_all/balanced），不做在线自适应 τ；
②双门不变量——`active_ref` 只在门禁通过/回滚后由 `on_promote()` 更新，被拒样本只写 `provisional_ref`；
③版本快照 + 回滚 + 哈希链审计 + kill-switch（fail-closed）。另外做了独立带内扰动负向测试（`scripts/negative_inband_test.py`）：8 类门禁边界用例全过、10 次带内候选放行 0/10、源码级断言 `active_ref` 只由 `reset_reference/on_promote` 写入（docs/06 §6.2）。边界：我们是单进程本地实现，
不声称 criteriond 的多副本容错；引用口径为"配套研究（J3，未投稿）"。

## 6 术语统一表 & 禁语清单（答辩口径一致，防止"每人一个说法"）

| 统一说法 | 不要说的 | 原因 |
|---|---|---|
| **playbook**（动作） | "策略/算子/工具"混用 | 策略=planner/bandit 层，动作=playbook，工具=Harness tool |
| **TTA** = 零标签仿射校准（`RECALIBRATE_AFFINE`） | "测试时增强/数据增强" | A7 关 TTA = 关掉仿射校准原语，不是图像增强 |
| **覆盖率 / 兑现率** | "命中率"含糊说法 | 覆盖率=候选内存在增益；兑现=门禁实际选中（docs/10 §7） |
| **漂移监测 / 诊断归因** | "检测/分类" | 与 docs/00-06 术语一致 |
| **受控 RSI** | "自我进化/自我修改" | 强调边界、可审计，避免被理解成失控 |
| **成本阶梯 / 最小充分动作** | "自适应重训" | 后者暗示无脑重训，恰是我们反对的 |
| **流式 macro-F1**（窗口平均） | "准确率/平均 F1"含糊说法 | 与基线表口径一致 |
| **B0 静态 / B1 周期重训 / B2 Oracle 上界** | "baseline/对照" | 三个基线必须分清 |
| **等效成本 scalar** | "GPU 小时" | 纯 CPU，用归一化成本；compute 权重 1.0 |

**禁语（绝对不说）**：
1. 不说没有跑出来的数字——所有数都能在 `results/SUMMARY.json` 找到；
2. 不说"完全解决/彻底安全/零风险"——受控 RSI 的边界是工程约束，不是数学证明；
3. 不说"合成数据等价于真实数据"——说"可控仿真 + AI4I 真实数据佐证 + adapter 接入路径"；
4. 不说"我们用了大模型"——说"LLM 驱动已用 mock 跑通闭环（+7.84pt、108,612 mock token），默认确定性、企业赛接 PyTRi0"；
5. 不说"模型是深度学习"——是 numpy MLP + 预提取特征，诚实反而得分；
6. 不把配套研究（未投稿）说成已发表，不把其结论外推成我们的安全证明。
