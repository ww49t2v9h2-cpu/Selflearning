# 12 · 系统运行说明（运行手册 / Runbook）

> 本文是**可照做的运行手册**：环境、安装、一条命令跑闭环、配置项、产物、FAQ、官方评测环境适配。
> 版本：v1.0 定稿（冻结于 2026-11-16 12:34，实验数字来自 `results/SUMMARY.json` 与 `results/acceptance.json`）。
> 维护：C（Harness/观测）起草 → Lead 汇总定稿。

## 1. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| OS | macOS / Linux（Windows WSL2 可用） | 已实测 macOS（Apple Silicon） |
| Python | **3.12**（3.10+ 兼容） | 评测机建议 3.10+，本机 3.12.14 |
| 运行依赖 | **numpy ≥ 1.24** | 系统本体只依赖 numpy + 标准库，纯 CPU |
| 可选依赖 | `swanlab`（实验记录上云/看板）、`openpyxl`（记录汇编 xlsx） | 缺失自动降级，不阻塞闭环 |
| 网络 | **运行期零网络**（安全要求） | 只有显式 `tracker.backend=swanlab mode=online` 或 LLM provider 才联网 |
| 磁盘 | 约 100~500 MB/全量 run（模型 npz + 记录 + 结果） | 可在 `RunContext.outdir` 配置 |
| 显存/GPU | 不需要 | numpy MLP，纯 CPU |

本仓库使用的解释器（若无系统 numpy，请用带 numpy 的 Python）：

```bash
PY=python3
$PY -c "import numpy, sys; print(sys.version, numpy.__version__)"
# 3.12.14 2.3.5
```

> 若评测环境自行创建 venv：`python -m venv .venv && . .venv/bin/activate && pip install numpy`
> 即可（无需其它系统依赖）。**禁止**在系统运行依赖里引入 torch/scipy/matplotlib。

```bash

$PY -m src.cli run --config configs/main.json --group main --seed 0
```

## 6. Harness 驱动模式

| `harness.driver` | `harness.provider` | 行为 | 网络 | token |
|---|---|---|---|---|
| `deterministic`（默认） | 忽略 | 规则驱动（skills 可执行子集），零 token | 无 | 0 |
| `llm` | `mock` | 完整 LLM JSON 工具协议（离线模拟） | 无 | 按字符估算 |
| `llm` | `openai_compat` | 真 LLM（PyTRi0 Qwen3.8-27B 等）；未配置/失败自动降级确定性 | 需显式配置 | 真实 usage |
| `auto` | 自动 | 真 LLM 可用才走 LLM，否则确定性 | 视配置 | 视配置 |

两者输出统一 `Trajectory`（steps/final_decision/tokens/wall_s/driver/outcome），
`Decision` 全字段（diagnosis/rationale/budget_before/after/cost/outcome/evidence_refs/safety）。
降级轨迹 `driver="llm-fallback"`，原因在 `outcome.fallback_reason`。

## 8. 常见问题（FAQ）

**Q1：`ModuleNotFoundError: No module named 'numpy'`？**
用带 numpy 的解释器（见 §1 的 `$PY`），或 `pip install numpy`。

**Q2：没装 swanlab 会报错吗？**
不会。SwanLab 是软依赖，缺失时 `SwanLabTracker.degraded=True` 自动降级为本地
SQLite/JSONL 记录，并写 `tracker_warnings.jsonl`；`query/export` 仍可查全部记录。

**Q3：评测现场没有网络，会不会卡住？**
不会。默认 `tracker.backend=local` + `harness.driver=deterministic`，**全程零网络**；
只有显式配置 SwanLab online / openai_compat 才会发起网络请求，且失败快速降级。

**Q4：LLM 返回非法 JSON / 不调工具怎么办？**
`LLMDriver` 严格校验（未知工具、非法参数、非法 chosen_playbook 都算失败），
连续 2 次失败自动降级 `DeterministicDriver`，轨迹标 `llm-fallback` 并记录原因；
若模型只在 final 里声称上线而没调 `deploy` 工具，**不会真的上线**（`deploy_not_executed=True`）。

**Q5：token 超预算？**
`budget.tokens_total` 是硬上限：余额 <256 时 LLM 驱动立即降级确定性；
`safety.max_tokens_per_decision` 是单次调用上限。全量 LLM 跑请按 `docs/07 §8.1` 上调预算。

**Q6：`STOP` 文件是干什么的？**
kill-switch：在工作目录创建 `STOP` 文件后，`run_experiment/deploy/request_labels` 等写动作
全部被拒绝（`rollback` 的 `emergency=true` 除外），审计日志记录原因。删除文件即恢复。

**Q7：为什么某窗口是 NOOP？**
正常且安全：无漂移/benign/repair/诊断置信度低/预算不足/phase 更新次数用满/所有候选被门禁拒。
`Decision.rationale` 与 `Decision.outcome.reason` 写明具体原因，`Trajectory.steps`
记录每次工具调用（被拒原因在 `error_kind`）。

**Q8：实验记录为空 / 查不到？**
确认 `experiments/runs/tracker.sqlite` 存在、`configs` 的 `tracker.dir` 一致；
`query_records.py --dir` 可显式指定目录；记录只在闭环 run 期间写入。

**Q9：xlsx 没生成？**
未安装 openpyxl → 自动降级为同目录 CSV（overview/metrics/costs）；
`pip install openpyxl` 后重新运行 `gen_record_book.py`。

**Q10：如何换官方数据包？**
实现/使用 `src/data/adapter.py` 的 `OfficialAdapter`，配置 `benchmark.adapter=official` 与
`benchmark.official_root`（模板 `configs/official_template.json`），详见 `docs/15`。

**Q11：如何复现某个 run？**
用同 `configs` + 同 `seed` + 同数据场景重新 `src.cli run`；记录里保存 `config_used.json`
与 `git_commit`。`src/cli.py repro` 可对比两次结果（见 README/docs/13）。

**Q12：跑得慢？**
主耗时在监测统计量（MMD/KS）与 playbook 训练；用 `configs/quick.json` 先验证，
全量 main 需数十分钟。图表脚本用独立 venv（matplotlib），不进入系统依赖。

## 10. 已知问题与限制

1. **SwanLab 未安装时的降级是预期行为**：本机校赛环境没有 swanlab（pip 二进制依赖受限），
   记录落本地镜像；联网环境 `pip install swanlab` 后 `swanlab sync` 即可上云（docs/08 §5）；
2. **LLM 全量跑 token 成本高**：默认预算只够演示/关键窗口，评测时按额度调 `budget.tokens_total`
   （详见 docs/07 §8.1）；
3. **决赛数据包-B 的脏数据类型未知**：已覆盖 NaN/异常值/传感器掉线；时间戳错乱、重复采样、
   多源缺失等规则需拿到官方数据后补充（见 docs/15 §11）；
4. **SwanLab 进程级单例**：同一进程只能一条活跃 SwanLab run，子实验以命名空间挂载
   （`{run_id}/{metric}`）；严格 1:1 用 `SwanLabTracker(attach_subruns=False)`；
5. **多进程写同一 tracker 目录不支持**：SQLite 单连接 + 线程锁，评测是单进程闭环；
6. **记录目录随时间增长**：可在提交前 `scripts/gen_record_book.py` 归档，或清理旧 run
   （记录本身不可变，删除目录等于删除审计证据，请谨慎）。

## 11. Docker 镜像（linux/amd64，提交用）

赛题要求提交 `docker save` 导出的单镜像、未压缩 tar。本仓库提供可复现构建：

```bash
# 任意 Docker 主机（Apple Silicon 用 buildx 跨构建；Linux/amd64 原生构建）
bash scripts/build_harness_docker.sh
# 产物：
#   deliverables/智训引擎_Harness_linux_amd64.tar          ← 经典布局，提交用（约 184MB，未压缩）
#   deliverables/智训引擎_Harness_linux_amd64_docker-save-raw.tar ← Docker 29 原始 docker save 输出（约 61MB，OCI hybrid）
```

脚本内部：
1. `docker buildx build --platform linux/amd64 --load -t zhixun-engine:1.0-linux-amd64 .`
2. `docker image inspect` 断言 `linux/amd64`；
3. `docker run --rm --platform linux/amd64 <image> info` 冒烟；
4. `docker save -o ..._docker-save-raw.tar <image>`（默认未压缩，不要 gzip）；
5. `python3 scripts/docker_save_to_classic.py <raw.tar> deliverables/智训引擎_Harness_linux_amd64.tar`
   转为经典 docker-archive（manifest.json + config.json + layer_*.tar，层解压为未压缩 tar）；
6. `python3 scripts/verify_docker_archive.py <tar>` 校验单镜像/架构/未压缩/层数；`docker load -i` 复测。

镜像约定：
- 入口 `python -m src.cli`，默认 `info`；运行产物写 `/app/experiments`、`/app/results`（app 用户可写）；
- 已内置 `numpy` 与 `data/external/ai4i2020.zip`；不含官方隐藏测试集；
- 平台：`linux/amd64`；单镜像（`manifest.json` 一条），`docker load -i` 可直接载入。
- 提交用 tar 为**经典布局**（`manifest.json` + `config.json` + `layer_*.tar`，无 OCI index/blobs）；
  原始 `docker save` 在 Docker 29 上会带 OCI layout，保留为 `..._docker-save-raw.tar` 备查。

```bash
# 使用
docker load -i deliverables/智训引擎_Harness_linux_amd64.tar
docker run --rm zhixun-engine:1.0-linux-amd64 run --config configs/quick.json
```
