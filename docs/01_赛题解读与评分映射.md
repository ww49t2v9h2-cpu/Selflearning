## 2. 关键约束与我们的处理

### 2.1 没有官方数据包（校赛阶段）
官方数据包尚未发放，且"隐藏测试流不公开、平台自动算分"。我们因此把问题**工程化地仿真**：
- 用可控合成漂移流（7 场景，覆盖赛题点名的 4 类漂移 + 2 类衍生机制）做主实验；
- 用公开工业数据（UCI AI4I 2020 预测性维护）做一次"真实数据上闭环仍成立"的佐证（`scripts/run_all.py --groups real`，见 results/real/）；
- 数据层与官方数据包之间用 **`DatasetAdapter` 接口**隔离，企业赛拿到数据后只换 adapter（docs/15），系统其余部分零改动；
- **决赛数据包-B（含脏数据）**：已实现 `RobustSanitizer`（缺失值/异常值/传感器掉线清洗，统计量只来自干净训练集），
  官方模板默认开启；压力测试见 docs/10 §8.5；
- 隐藏测试的仿真：数据生成时按 2/3 可见流 + 1/3 隐藏流切分；系统只能通过 `LabelOracle` 按预算取可见流标签，隐藏流标签只有 `HiddenEvaluator` 能读。**"标注预算"与"隐藏评测"两个约束在仿真里是真实生效的，不是摆设。**

### 2.2 没有 PyTRi0 额度、没有 SwanLab 云账号
- Harness 的 LLM provider 做成可插拔：默认 `deterministic`（离线、零 token、可复现）+ `mock`；企业赛改为 `openai_compat` 指向 PyTRi0 的 Qwen3.8-27B（或自训模型），**接口、计量、降级路径已就绪**；
- 实验记录：`SwanLabTracker` 完整实现 online/local/offline 三种模式；校赛阶段用 **offline 模式**（数据落本地、后续 `swanlab sync` 上云）+ 本地 SQLite 镜像双写；即使没装 swanlab 也能进"local 降级"模式，不影响闭环。

### 2.3 "单位增益消耗"意味着不能无脑重训
这是本赛题与普通"域适应比赛"最大的区别：**不更新也是合法策略**（NOOP），**更新必须证明花得值**。
- 监测器只在统计显著时才触发诊断（避免每个窗口都烧算力）；
- 诊断器先估"可恢复性"（用预算内的探针标签实测仿射校准增益），再决定是否值得花标注；
- 规划器按 $(\text{先验增益})/(\text{估计成本})$ 排序并做 cheapest-first 探索；
- 门禁要求增益超过阈值才上线，否则 SHADOW_ONLY / NOOP；
- 主实验同时报告 **增益** 与 **成本**，并做"固定成本预算下增益"曲线。

### 2.4 受控 RSI：不是"让大模型随意改自己"
我们的"递归自改进"有明确边界：
- **模型层**：champion 版本只通过 registry 变更，版本不可变、lineage 完整、随时可回滚；
- **策略层**：planner 的 (诊断类型 → playbook) 策略表用 bandit 从实际结果更新，**只更新数值先验，不更新可执行代码**；
- **禁止项**：动作白名单之外不允许任何操作；系统运行期无网络；高风险动作（类别扩展/重训）必须记录升级；
- **熔断**：预算耗尽、连续失败、kill-switch 文件出现、审计链校验失败 → 立即停止更新并保守回退。

## 4. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 官方数据格式与仿真差异大 | 企业赛适配成本 | adapter 隔离 + 官方数据格式假设写进 docs/15，企业赛拿到数据后先用 `OfficialAdapter` 跑校验脚本 |
| 隐藏测试流存在未知漂移类型 | 策略表覆盖不到 | 监测器 novelty 分支 + 兜底 `NOOP/SHADOW_ONLY`；诊断不确定时不乱花钱 |
| 合成基准被质疑"太理想" | 论证可信度 | 公开真实数据佐证 + 消融 + 明确写出仿真边界（docs/09 风险节） |
| 预算口径与平台不一致 | 客观分吃亏 | 给三套权重下的成本-增益敏感性分析；核心结论用 Pareto 而非单点分数 |
| LLM 驱动的延迟/成本不可控 | 超时/超预算 | 确定性驱动为默认；LLM 驱动有 max_steps/token 硬门，失败自动降级 |
