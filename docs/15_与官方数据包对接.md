# 与官方数据包对接（数据契约、接入流程与风险）

> 目标：校赛/正式赛拿到官方数据包后，**只替换数据适配层**（`src/data/adapter.py`），
> 闭环（`src/loop.py`）、引擎、Harness、观测与基线代码无需任何改动即可运行。
> 对应实现：`src/data/adapter.py::OfficialAdapter`、配置模板 `configs/official_template.json`、
> 测试 `tests/test_data.py::TestOfficialAdapter`。

---

## 1. 原则

1. **接口不变**：官方数据 → `Benchmark`（字段与 `src/data/synth.py` 中冻结的 `Benchmark` 完全一致），
   由 `DatasetAdapter.load(root, cfg) -> Benchmark` 统一产出。
2. **标签隔离**：部署流 `stream.csv` 物理上不含标签列（loader 发现标签列会直接报错，防泄漏）；
   visible 标签放在独立的 `stream_labels.csv`，只能经 `LabelOracle` 按预算发放；
   hidden 标签只进 `Benchmark.hidden_by_chunk`，由评测器消费，绝不进入系统快照/决策/记录。
3. **运行期零网络**：官方数据以静态文件落盘；loader 只读本地文件。下载/解压仅发生在准备阶段。
4. **可复现**：`manifest.dataset_version` + 文件 sha256 + `Benchmark.meta` 写入每次 run 的
   `config_used.json`/`record.json`；同一数据包 + 同一 seed 结果一致。
5. **口径一致**：评测一律使用隐藏测试的 macro-F1/accuracy（评测类别数 = `Benchmark.n_classes`）；
   与合成基准的 B0/B1/B2 基线脚本 `scripts/baseline_suite.py` 共用同一套指标代码。

## 2. 官方数据包目录格式（`official_root`，默认 `data/official/`）

```
data/official/
├── manifest.json       # 必需：数据包元信息（见 §3）
├── base_train.csv      # 必需：初始有标签训练集
├── base_val.csv        # 必需：初始验证集
├── stream.csv          # 必需：部署流（无标签），含 id/chunk/phase + 特征列
├── stream_labels.csv   # 必需：visible 标注（id, label），LabelOracle 的数据来源
└── hidden.csv          # 必需：平台隐藏测试（chunk + 特征 + label）
```

> 官方若发布的是别的文件形态（例如每个阶段一个 parquet、或 jsonl 流），
> 只需在 `OfficialAdapter` 的读取函数里做一次转换，**不要改闭环代码**。

### 2.1 `base_train.csv` / `base_val.csv`

| 列 | 必需 | 说明 |
|---|---|---|
| `feature_columns`（manifest 指定，如 `f0,f1,...,f{d-1}`） | 是 | 预提取特征，数值型，无缺失 |
| `label`（manifest `label_column` 指定） | 是 | 初始类别，取值 `0..base_classes-1` |

示例（d=4）：
```csv
f0,f1,f2,f3,label
0.12,-1.03,0.55,0.02,0
-0.30,0.88,1.20,-0.11,2
```

### 2.2 `stream.csv`（部署流，**无标签**）

| 列 | 必需 | 说明 |
|---|---|---|
| `id` | 是 | 官方原始样本 id（唯一；加载后会重新编号，见 §4） |
| `chunk` | 是 | 窗口号；**同一 chunk 只能属于一个 phase**，chunk 号升序 = 时间顺序 |
| `phase` | 是 | 漂移阶段编号，`0..len(phase_names)-1` |
| `feature_columns` | 是 | 与 base 相同的特征列，无缺失 |

示例：
```csv
id,chunk,phase,f0,f1,f2,f3
100001,0,0,0.11,-1.02,0.53,0.00
100002,0,0,-0.28,0.90,1.18,-0.10
...
```
加载后每个 chunk 变为一个 `StreamChunk(t, phase, ids, x, meta)`，`x` 形状 `[n, d]`。

### 2.3 `stream_labels.csv`（visible 标注）

| 列 | 必需 | 说明 |
|---|---|---|
| `id` | 是 | 必须属于 `stream.csv` 的样本；重复行按最后一次覆盖 |
| `label` | 是 | 取值 `0..n_classes-1`；可含 novel 类（≥ `base_classes`） |

- 只包含**部署流上允许被标注**的样本；可以只是 stream 的子集（模拟"标注预算有限"）。
- 该文件不是隐藏标签，系统可通过 `LabelOracle.query(ids, reason)` 按预算取用；
  `SyntheticOracle`/`VisibleLabelOracle` 会去重、按 `budget.labels_total` 硬截断并记账 `Cost`。

### 2.4 `hidden.csv`（平台隐藏测试）

| 列 | 必需 | 说明 |
|---|---|---|
| `chunk` | 是 | 对应 `stream.csv` 的窗口号；每个部署 chunk 必须至少有一行隐藏测试 |
| `feature_columns` | 是 | 与 stream 相同特征 |
| `label` | 是 | 评测标签，`0..n_classes-1`（含 novel 类） |

- 隐藏测试与 visible 最好**同分布**（随机划分），否则指标有偏；请官方确认或记录划分方式。
- loader 按 `chunk` 分组后均分到对应 `hidden_by_chunk`；评测器对每窗口算
  macro-F1/accuracy，再按 phase 聚合（`scripts/baseline_suite.py` 同口径）。

## 3. `manifest.json` 字段

| 字段 | 必需 | 类型 | 说明 |
|---|---|---|---|
| `schema_version` | 是 | str | 数据契约版本，当前 `"1.0"` |
| `name` | 是 | str | 数据包名，写入 `Benchmark.name` |
| `dataset_version` | 建议 | str | 官方版本/发布时间，写入 meta 以便追溯 |
| `base_classes` | 是 | int | 初始模型输出类别数（不含 novel） |
| `n_classes` | 是 | int | 评测类别总数（含 novel）；`class_names` 长度须一致 |
| `class_names` | 是 | list[str] | 类别名（长度 = n_classes） |
| `phase_names` | 是 | list[str] | 阶段名（长度 ≥ max(phase)+1） |
| `feature_columns` | 是 | list[str] | 特征列名，顺序即模型输入维度顺序 |
| `label_column` | 否 | str | 默认 `"label"` |
| `chunk_column` | 否 | str | 默认 `"chunk"` |
| `id_column` | 否 | str | 默认 `"id"` |
| `d_features` | 否 | int | 若给出必须等于 `len(feature_columns)` |
| `checksums` | 否 | dict[str,str] | `{文件名: sha256}`；给出则 loader 校验，失败即拒绝加载 |
| `license` / `description` / `note` | 否 | str | 许可与说明，写入 meta |

`checksums` 示例：
```json
{"checksums": {"base_train.csv": "ab12...", "stream.csv": "cd34..."}}
```

## 4. 编号与 id 契约（重要）

- 加载后 visible 样本按 chunk 时间顺序**统一重新编号为 `0..N-1`**，保证
  `Benchmark.visible_y[id]` 即该 id 的标签（`SyntheticOracle` 的约定）。
- 官方原始 id 保留在 `chunk.meta["source_ids"]` 与 `meta["official_chunk"]`，便于审计回溯。
- hidden 样本不参与编号，按 chunk 对齐放进 `hidden_by_chunk[chunk]`。
- 因此：**不要在 stream 中跳号/重复 id**；重复会在重编号后丢失对应关系。

## 5. 标注 oracle 接线

```python
from src.data.adapter import OfficialAdapter, VisibleLabelOracle

bench = OfficialAdapter().load(root="data/official", cfg=cfg)
oracle = VisibleLabelOracle(bench, labels_total=cfg["budget"]["labels_total"])
qr = oracle.query(bench.chunks[0].ids[:6], reason="monitor_probe")
# qr.ids / qr.y / qr.cost.labels；预算耗尽后返回空，永不超发
```

- 与合成基准完全相同的 `LabelOracle` 协议（`query/remaining/budget_state`）；
- 系统侧的 monitor 探针、playbook 的 `LAST_LAYER_FT`/`RETRAIN_MIXED` 等 playbook 都经此取标签；
- 所有 query 都会记录 `reason`、条数与累计预算，进入 `Cost.labels` 与审计日志。

## 6. 评测接线（hidden 不可见）

- `loop.py`/`evaluator` 只把 `HiddenScore`（含 t/phase/macro_f1/accuracy/per_class_recall）
  写入 `RunRecord.metrics`/`MetricPoint`；**不得**把 `hy` 写进系统可见的 snapshot 或决策记录。
- 模型选择只能使用 `probe_macro_f1`（oracle 探针）或代理指标；
  隐藏分数仅用于**事后评测**与基线对比（`scripts/baseline_suite.py` 同一口径）。
- 建议接入后立即跑一次 B0 静态基线（`baseline_suite.py --scenarios ...` 换成官方场景）：
  得到官方数据"静态难度曲线"，用于判断漂移强度并校准门禁阈值。

## 7. 接入 SOP（拿到官方数据后 10 分钟）

1. **落盘**：把官方包解压到 `data/official/`，按键名核对 §2 文件清单；
2. **自检**：
   ```bash
   PY=/Users/mb/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3
   $PY - <<'PY'
   from src.data.adapter import OfficialAdapter
   print(OfficialAdapter().validate("data/official"))
   PY
   ```
   期望 `ok: true`；若 `problems` 非空，按提示补文件/改列名；
3. **冒烟加载**：
   ```bash
   $PY - <<'PY'
   from src.data.adapter import OfficialAdapter
   from src.core.model import MLP
   b = OfficialAdapter().load("data/official", {})
   print(b.describe())
   m = MLP(b.d, b.base_classes, seed=0).fit(b.base_x, b.base_y, epochs=5)
   print("val:", m.predict(b.val_x)[:5])
   PY
   ```
4. **改配置**：复制 `configs/official_template.json` 为 `configs/official.json`，
   确认 `benchmark.adapter="official"`、`benchmark.official_root`、预算字段；
5. **跑基线**：把 `scripts/baseline_suite.py` 的 `--scenarios` 换成官方阶段（或加一个
   `bench_factory` 入口），先跑 B0 静态难度；
6. **跑闭环**：`$PY -m src.cli run --config configs/official.json`；
7. **归档**：把 `manifest.json` + 各文件 sha256 + 运行命令写入 `experiments/` run 的
   `config_used.json`，答辩材料引用数据版本与许可。

## 8. 错误与降级

| 场景 | 行为 |
|---|---|
| 目录/文件缺失 | `FileNotFoundError`，消息列出缺失文件与 docs/15 指引，并给出 synth 回退提示 |
| manifest 非法 JSON / 缺字段 | `FileNotFoundError`（validate 阶段汇总问题）或 `ValueError`（字段级） |
| 特征列缺失 / 缺失值 | `ValueError`，指出文件与缺失列名（最多列 8 个） |
| `stream.csv` 含 label 列 | `ValueError`：拒绝加载，防止标签泄漏 |
| `stream_labels.csv` id 不属于 stream | `ValueError`，指出越界 id |
| chunk 内 phase 不唯一 / phase 越界 | `ValueError` |
| hidden 缺某 chunk | `ValueError`（每个部署窗口必须有隐藏评测集） |
| checksum 不匹配 | `validate` 返回 `ok:false`；`load` 拒绝加载 |
| 官方数据包迟迟未发 | `benchmark.adapter="synth"` 继续校赛闭环；所有实验/文档可复现 |

## 9. 风险清单与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 官方格式与本文档不一致 | 加载失败 | 适配器内做一次性转换（保持 `Benchmark` 不变）；先 `validate` 再 `load` |
| 特征维度/列名变化 | 模型输入维度变化 | 全部由 `Benchmark.d`/`manifest.feature_columns` 驱动，模型/引擎不硬编码 48 |
| 类别数变化（novel 是否单独计） | 评测口径不一致 | `base_classes`/`n_classes` 显式声明；评测统一用 `n_classes` macro-F1 |
| 隐藏测试划分方式未知（是否同分布） | 指标有偏 | 要求官方文档说明；否则记录"划分方式未知"并在结论中声明 |
| 官方漂移强度未知（可能很弱/很强） | 门禁阈值失准 | 先跑 B0 静态难度探针 + 与合成 S1-S7 对照，再按 `docs/06` 校准阈值 |
| 标注预算与官方口径不同 | Pareto 不可比 | 所有方法统一 `Cost` 记账（`labels/compute_units/tokens`），基线 B1/B2 也记账 |
| 数据许可/引用缺失 | 答辩合规问题 | `manifest.license` + `data/external/README.md` 记录出处；引用官方数据说明 |
| 训练/评测时间超限 | 现场演示失败 | 数据加载后一次性 numpy 化 + 模型为纯 numpy MLP；官方数据规模先在本地压测 |

- 配置模板：`configs/official_template.json`

## 11. 决赛数据包-B / 脏数据适配（2026-11 新增）

官方速览视频明确：北京市决赛换用**数据包-B（规模更大、漂移更复杂、可能混脏数据）**，总决赛考察泛化与抗干扰能力。
对应适配：

1. **特征清洗**：`src/core/preprocess.py::RobustSanitizer`（纯 numpy）
   - 拟合：只用干净初始训练集 `base_x` 估计每维中位数与 0.1%/99.9% 分位截断界；
   - 推理：非有限值（NaN/Inf）→ 训练集中位数；越界值 → 分位截断；每次 transform 记录修复量入运行记录（可审计）；
   - 接入：`loop.py` 逐窗口清洗后送入监测/诊断/动作；`HiddenEvaluator` 对隐藏测试流使用同一清洗器（训练/推理一致）。
2. **配置**：`configs/official_template.json` 默认 `"data": {"sanitize": true}`；
   `configs/main.json` 为匹配冻结主实验保持 `sanitize: false`（实测干净数据上差异很小（<0.1pt），为保持冻结一致性默认关闭）。
3. **压力测试**：`scripts/stress_dirty_data.py` 注入 NaN/异常值/整块传感器掉线，
   结果见 `results/dirty/summary.md` 与 docs/10 §8.5（重度脏数据：清洗后 0.704 vs 静态 0.694；不清洗 0.159）。
4. **待接入的数据包-B 细节**（拿到官方数据后确认）：
   - 时间戳错乱/重复采样/多源缺失的清洗规则；
   - 脏数据类型与比例（决定 clip 分位与填充策略）；
   - 是否需要"缺失指示特征"（把 NaN 位置作为额外列，交给模型学习）；
   - 官方评测是否允许写入运行目录/网络隔离方式。
5. **泛化余量设计**（对应"抗干扰"）：TTA 只用可逆仿射校准；无标签监控 + 探针门禁 + NOOP/回滚；
   脏数据下若监测置信度低，系统倾向 NOOP 而非错误上线（压力测试中重度脏数据仍保持 +1.02pt 增益）。

## 12. 官方 CPU-A/B/C 数据包训练结果（2026-11-23）

已用官方三份数据包完成基线续训与官方 CPU-A 跨批次适应对照（CPU-only，numpy）：

| Profile | 官方任务 | 初始验证 | 最优验证 | 提升 | 最优配置 |
|---|---|---|---|---|---|
| A | 气体传感器 6 类（Macro-F1） | 0.7140 | **0.7258** | **+0.0118** | epochs=20, lr=0.001 |
| B | XJTU-SY RUL（RMSE 分钟） | 681.16 | **642.63** | **−38.53** | epochs=40, lr=0.003 |
| C | C-MAPSS RUL（RMSE 循环） | 52.87 | **52.12** | **−0.75** | epochs=10, lr=0.001 |

官方 CPU-A 跨批次适应（batch1 训练，batches 3–10 逐批 20% 标签适应 / 80% 测试）：
static **0.3199** → 零标签 TTA **0.5528（+0.2329）** → 全量 FT+回放 **0.4983（+0.1784）**；
末层 FT 在强漂移下退化（0.2160）。这为"先零标签 TTA、证据不足再花标签"的成本阶梯提供了官方数据对照证据。

整包闭环（monitor 重校准 + 动作白名单，排除 PRIOR_CORRECTION）3 seeds 全部正增益：
静态 0.1513 → 自进化 **0.3061（+15.48pt）**，标注 345/360，1 次部署/0 回滚
（`results/official/cpu_a_evolving_robust/`）。

官方任务预测器：`deliverables/official_predict/predict.py`（纯 NumPy，读官方 checkpoint，A/B/C 通用，
stdin→stdout 官方协议）；三份自检报告见 `deliverables/official_predict/selfcheck_{A,B,C}.json`，
与官方 `predict.py` 逐样本最大绝对差 **0.0**。打包：`deliverables/官方任务预测工具.zip`。

- 报告：`deliverables/官方数据包训练报告.pdf`；明细 `results/official/`；
- 脚本：`scripts/train_official_baselines.py`、`scripts/eval_official_cpu_a_adapt.py`；
- 边界：只用公开 train/validation；B 的 RUL 由完整寿命记录确定性计算（label_provenance=draft）；
  C 只使用公开 train/validation；本地验证不能替代官方隐藏测试。
