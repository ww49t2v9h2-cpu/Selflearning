# 技术路线论证：从"训练师微调"到"受控双层自进化"

> 结论先行：**单一"微调训练师"路线和单一"LLM Agent Harness"路线都不适合本题的预算约束；
> 我们用"数值模型层自迭代 + 策略层可学习调度 + LLM 只做低频开放式决策"的混合双层架构（受控 RSI）。**
> 本文给出形式化问题、三条路线的成本/能力对比、选择理由、可证伪假设与消融设计。

---

## 1. 问题形式化

部署流按窗口到达：$\mathcal{D}_t=\{x_i^{(t)}\}_{i=1}^{n}$（**无标签**），其潜在分布 $P_t(x,y)$ 随
$t$ 变化（磨损/老化/工况/新故障/维修复位）。系统持有初始模型 $f_{\theta_0}$（在 $\mathcal{D}_0$ 训练），
只能通过**标注 oracle** 以预算 $L$ 获取少量标签，以算力预算 $C$ 与 token 预算 $T$ 完成更新。

目标（对齐平台客观分"单位增益消耗"）：

$$
\max_{\pi}\quad
\frac{\displaystyle \int_t \big[\mathrm{F1}_t(f_{\theta(t)})-\mathrm{F1}_t(f_{\theta_0})\big]dt}
{\displaystyle \lambda_C \cdot C_{\text{used}} + \lambda_L \cdot L_{\text{used}} + \lambda_T \cdot T_{\text{used}}}
\quad \text{s.t.}\quad
\begin{cases}
\text{最终性能} \ge \text{静态基线（部署后不再更新的模型）}\\
\text{动作} \in \text{白名单},\ \text{无网络},\ \text{可审计}\\  
\text{回滚可用、预算不得超支}
\end{cases}
$$

其中 $\pi$ 是一个**策略**：在每个触发窗口决定"是否更新、更新什么、花多少预算"。
这正是赛题"模型层自迭代 + 策略层自改进"要优化的对象。注意目标函数的分母意味着：
**NOOP 也可能比一次错误更新更优**；任何一次更新都必须用实测增益证明自己。

## 2. 三条候选路线

### R1 纯"训练师"微调（Fine-tune-only Trainer）
**做法**：检测到漂移后，用新数据（或加上回放）微调一个小模型/大模型；不区分漂移类型，
不做归因，不做预算调度。

- 优点：实现简单、结果可预期、无 LLM 依赖、易审计。
- 缺点：
  1. **成本高**：每类漂移都触发全量更新；senor gain 这种零标签可解的漂移（仿射校准即可）也会烧掉标注；
  2. **没有归因**：无法回答"为什么失准"，学术与答辩上少一半说服力；
  3. **策略不学习**：同样的漂移重复犯错，不满足"策略层自改进"；
  4. 对开集新故障（S4）无能为力：闭集重训无法输出新类。
- 定位：**兜底基线 B1**（周期重训）与 oracle 上界 B2 的参照，不作为最终路线。

### R2 纯 Agent Harness（LLM 全权驱动）
**做法**：让 PyTRi0 Qwen3.8-27B 通过 Tools/Skills 直接决定每一步（调用训练、评估、上线）。

- 优点：解释性好、可扩展、能处理开放式情形（新故障命名、报告生成）。
- 缺点：
  1. **Token 成本与延迟**：每个窗口多次决策，按 PyTRi0 定价（Qwen3.8-27B 训练/采样 ¥25.29/M、
     Prefill ¥8.41/M）单次 4k prompt + 500 output ≈ ¥0.05；60 窗口×每窗 3–5 次调用 ≈ ¥10–20/run，
     且 token 直接进客观分分母；
  2. **数值决策不稳定**：阈值判定、超参选择这类高频低层决策交给 LLM 既不便宜也不可靠；
  3. **隐藏流上无法人工兜底**：封闭评测要求无人干预，LLM 一旦格式/工具调用失败就是事故；
  4. 可复现性差（温度/版本漂移）。
- 定位：**只保留在"低频、开放式、需要解释"的决策点**（见 §3 分工），并作为可插拔驱动。

### R3 混合双层（本方案）
**做法**：

```
高频数值决策（每窗口）  ：监测器 + 诊断器 + bandit 规划器 + 门禁 —— 确定性、零 token、可复现
中频学习决策（每漂移）  ：playbook 候选实验（9 种动作）+ 预算内 successive halving —— 数值学习
低频开放式决策（每阶段）：LLM/人工可选的诊断总结、实验设计建议、报告生成 —— 可插拔、可关闭
                ↘ 策略层：把"诊断类型 → playbook → 实际增益/成本"写回策略表（bandit 更新）
```

- 模型层自迭代 = playbook 产生的模型版本在 registry 中滚动；
- 策略层自改进 = planner 的后验/策略表随经验更新（只更新**数值**，不更新可执行代码）；
- 受控 RSI = 白名单 + 预算硬门 + 高风险升级 + kill-switch + 哈希链审计；
- LLM 是可选项：`harness.driver=deterministic`（默认，离线）或 `llm`（企业赛接 PyTRi0）。

**为什么这是最优解**：把"贵且不确定"的 LLM 从高频回路里拿掉，换成本几乎为零的
确定性策略 + 在线 bandit；同时保留 LLM 在真正需要语言理解的位置（原因解释、实验设计、
报告），既不浪费 token，也满足赛题"可由工具（Tools）与技能（Skills）组成的智能体 Harness"的要求
——我们的 Harness 是真实存在的（12 个工具 + 6 个技能 + 两种驱动），只是默认驱动是确定性策略，
LLM 驱动作为可插拔增强。

### 路线对比矩阵

| 维度 | R1 纯微调 | R2 纯 LLM Harness | **R3 混合双层（本方案）** |
|---|---|---|---|
| 单位成本增益 | 低（每漂移都重训） | 中低（token 计入成本） | **高（按诊断选择最便宜有效动作）** |
| 归因能力 | 无 | 有（但依赖 LLM 质量） | **有（统计证据 + 可审计）** |
| 开集新故障 | 不支持 | 支持（不稳定） | **支持（NOVEL_CLASS_EXTEND）** |
| 可复现性 | 高 | 低（温度/版本） | **高（默认确定性；LLM 模式可固定 seed/temperature）** |
| 无网络离线 | 自然满足 | 需本地模型 | **默认满足** |
| 策略层自改进 | 无 | 隐含在 prompt 里 | **显式 bandit 策略表，可审计** |
| 受控 RSI 可证 | 弱 | 弱（LLM 可被诱导） | **强（白名单/预算/审计/回滚）** |
| 企业赛迁移 | 一般 | 需额度与网络 | **LLM 模式一条配置切换** |

### 2.4 相关工作与定位（2024-11 ～ 2026-11，详见 docs/16）

近两年"自进化/受控 RSI"从设想变成公司级工程议程，也把我们的表述逼到必须精确：

- **开放式自改进已很强**：AlphaEvolve（arXiv:2506.13131）用评估器驱动的进化搜索优化算法/调度/TPU 电路，
  并加速其自身底层 LLM 训练；DGM（arXiv:2505.22954）、SEAL（arXiv:2506.10943）、Absolute Zero（arXiv:2505.03335）、
  R-Zero（arXiv:2508.05004）等把"自改代码/自编辑权重/零数据自博弈"推到开源可复现。
- **"门禁式自进化"2026 年集中出现**：VaG（arXiv:2608.05810）论证技能污染不可逆、预提交门禁优于事后回滚；
  Bilevel Autoresearch（arXiv:2603.23420）做机制级双层 RSI 并明确需要门禁/版本/回滚；
  Gated 动力学（arXiv:2610.03243）给出"评估器必须留在被评估种群之外"的分离定理；
  Self-Improvement Problem（arXiv:2610.21646）证明通用门禁不可兼得可靠与非保守，但**有界评估+有限提案预算**可恢复保证。
  → 我们**不声称首创门禁/回滚**；门禁与回滚是合规底线。
- **TTA 的无条件收益已被证伪**：延迟审计（arXiv:2610.12232）显示无泄漏 harness 下 TTA 增益被高估、简单基线常胜复杂 TTA；
  CTTA 综述（TMLR 2026，arXiv:2607.08164）指出遗忘与伪标签误差累积是两大失败模式。
  → 这正是我们"探针实测增益→门禁→否则 NOOP"的依据（arXiv:2610.21646 的 bounded regime 与我们的预算硬门同构）。
- **Agent Harness 已成工程学科**：Anthropic 的 MCP→Claude Code→Skills→"评估器必须独立/harness 假设会过期"（2024-11～2026-10）、
  OpenAI 的 AgentKit Evals/改进飞轮/Harness engineering（2025-10～2026-05）已成体系。
  → 有 Harness 不构成新颖性；差异在**工业闭环 + 预算治理 + 可审计回滚**。
- **工业侧缺口真实存在**：华为盘古预测大模型在万华 2000+ 设备把预测准确率 70%→90%，软通天璇 MaaS/数智本体平台
  覆盖模型接入—微调—部署；但两家公开材料描述的是"生产过程控制闭环"，**没有"模型质量自愈"的控制回路**。
  → 我们的定位是"在既有工业基座之上补齐自动决策—门禁—回滚控制回路"，而不是"填补工业 AI 空白"。

**我们的三条可主张贡献（写法按文献校准）**：
**N1 双层受控 RSI 的系统闭环**（有界动作空间 + 预算硬门 + 探针门禁 + 版本回滚 + 哈希链审计 + kill-switch；
模型层 playbook 版本滚动 / 策略层 bandit 数值先验，两级可分别回滚）；
**N2 无标签漂移流上的"诊断→假设→探针门禁"耦合**（漂移归因作为实验先验，探针标签构造临时验证器，
NOOP 合法；A2 消融 +0.00 与 A7 消融 -0.56 为其证据）；
**N3 部署级可复现/可审计评测协议**（run_id + 配置快照 + SQLite 镜像 + SwanLab 兼容 + 哈希链 +
七场景基准 + A1–A7 验收 + 负向安全测试 + 一键复现）。
**边界**：不做权重级/代码级递归自改；不声称通用 RSI 安全；不把"漂移检测"当核心创新（已商品化）。

**配套研究（J1–J3，未投稿）的分工**（详见 `notes/J1-J3_在项目中的角色.md`）：
- **J1 外部信道必要性**：闭合自指回路可含马蹄/正熵、一般情形不可判定 → 自改进必须有外部正确性信道，
  对应我们的"探针标签 + 平台评测隔离 + 预算化标注"；
- **J2 采样/验证器经济学**：覆盖率≠兑现，兑现由验证器拒绝什么决定；N=1 常计算最优、串行=并行决策函数
  但并行 5–8× 成本 → 对应我们的"单候选 cheapest-first 串行 + NOOP 合法 + 预算硬门"；
- **J3 判据可靠性**：判据是有状态、可复制对象，会按方向失效（滚动中位数→接受一切、EMA→拒绝一切），
  双门隔离可恢复严格门质量 → 对应我们的 `active_ref/provisional_ref` 双门不变量、版本快照与回滚。
引用均标注"配套研究（未投稿）"，只作为设计依据，不作为性能/安全证明。

## 3. 双层自进化的具体机制

### 3.1 模型层：9 个 playbook 的"成本阶梯"

| playbook | 需要的标签 | 算力量级 | 适用诊断 | 风险 |
|---|---|---|---|---|
| `NOOP` | 0 | 0 | benign / 预算不足 | low |
| `RECALIBRATE_AFFINE`（TTA） | 0 | ~0 | covariate_affine（增益/偏置老化） | low |
| `PRIOR_CORRECTION` | 0 | ~0 | label_shift | low |
| `LAST_LAYER_FT` | 20–60 | 低（只训头） | 轻度 concept / 小样本 | low |
| `FULL_FINETUNE_REPLAY` | 60–150 | 中（回放+微调） | condition_switch / concept | medium |
| `RETRAIN_MIXED` | 120–250 | 中高（从零重训） | 严重 concept / 多机制混合 | medium |
| `NOVEL_CLASS_EXTEND` | 100–200 | 中高（扩展+训练） | novel_class | high（升级） |
| `SHADOW_ONLY` | 0 | 低（只评估） | 门禁边缘/不确定 | low |
| `ROLLBACK` | 0 | 0 | repair / 上线后回退 | medium |

成本阶梯的设计原则：**能用 0 标签解决的绝不用标签；能用线性头解决的绝不全量微调；
必须全量微调的先回放再训练；新类必须显式扩展而不是硬映射到旧类。**

**关键原语：测试时自适应归一化（TTA）。** 传感器老化/工况切换中的仿射成分可以完全在推理时
用当前 batch 的统计量对齐回源域解决：`x' = (x-μ_t)/σ_t·σ_s + μ_s`，不更新任何参数、不需要标签。
把它做成"版本可部署"的候选（模型带 `adaptive` 标记，npz 存取不丢），既避免了"把目标域 scaler
固化进模型版本、下一阶段反而失配"的经典坑，又让同一版本跨窗口泛化。实测（3 seeds 均值）：
仅此原语即可让 S7 流式 F1 从 0.701 → 0.815、S1 +16.4、S3 +20.1（见 `results/diagnostics/adaptive_tta.json`）；
在 S6 标签先验漂移上它会 -11pt，但门禁在探针标签上会拒绝该候选——这正是"诊断 + 门禁"协同的价值。

### 3.2 策略层：bandit 策略表（受控）

- 状态：`(diagnosis_kind, 漂移严重度分箱, 剩余预算分箱)`；
- 动作：playbook（经白名单过滤）；
- 收益：$r = \Delta\mathrm{F1}_{\text{gate}} - \lambda\cdot\text{cost}$（门禁通过的增益扣成本）；
- 更新：对每个 (状态, 动作) 维护 Beta/Gaussian 后验，Thompson 采样选动作（探索率可配）；
- 持久化：每个 run 的工作目录 `experiments/runs/<run_id>/strategy_policy.json`，每次更新记录
  "旧先验→新先验→依据 run_id"，这样"策略层自改进"不是一句口号，而是可 diff、可审计的文件状态。
  默认**按 run 隔离**（跨 run 不继承，保证不同 seed/配置的评测公平与可复现）；
  需要跨 run 累积经验时设 `engine.planner.policy_scope="global"`。

**受控边界**：策略层只能改先验数值和候选排序；不能新增 playbook、不能改门禁阈值、
不能改预算、不能触碰文件系统/网络。任何越界尝试由 SafetyGuard 拒绝并写审计日志。

### 3.3 为什么 LLM 只做低频决策（成本论证）

以 PyTRi0 Qwen3.8-27B 公开定价（¥25.29/M 训练·采样、¥8.41/M Prefill、¥1.68/M Cached，16k 上下文）估算：

| 决策类型 | 频率 | 单次 token | 单 run token | 是否值得 LLM |
|---|---|---|---|---|
| 每窗口阈值/是否触发 | 60 次/run | ~0（确定性） | 0 | 否 |
| 每漂移诊断归因总结 + 实验设计 | 3–6 次/run | 4k prompt + 600 out | ~28k | 可（解释性收益） |
| 报告生成/答辩材料 | 1–2 次/run | 8k+ | ~20k | 可（离线生成） |

按上表，若每窗口都用 LLM，token 会变成主要成本项；而**只在每漂移事件用一次 LLM 做归因解释与
实验设计摘要**，token 只占次要成本，同时保留了"Harness/Agent"的完整语义。这也是我们默认
`deterministic` 驱动、把 `llm` 驱动做成可插拔的定量理由。

## 4. 闭环状态机

```
每个窗口 t:
  1. 观测：predict(x_chunk) → 记录置信度/熵/预测分布（无标签）
  2. 监测：MMD/KS/代理指标/novelty/探针准确率 → DriftEvent[]
     ├─ 无显著事件 → NOOP，进入下一窗口（零成本，仅记账）
     └─ 有显著事件 ↓
  3. 诊断：DriftEvent + 统计证据 → Diagnosis(kind, severity, affected_*, prior_delta, recommended[])
  4. 规划：白名单/预算过滤 → 候选 playbook（先验 × 成本） → 排序（cheapest-first）
  5. 实验：对前 k 个候选做小预算实验（标签预算内）→ 候选指标（probe/稳定性/类召回）
  6. 门禁：候选 vs champion → GateResult(promote|shadow|reject)
  7. 上线/回滚：registry.promote / rollback；更新 champion
  8. 策略学习：planner.update_strategy(kind, playbook, reward, cost)
  9. 记录：RunRecord/MetricPoint/Decision/Audit 落盘（+ SwanLab）
 10. 上线后看门狗：性能持续下跌 → ROLLBACK（回到上一稳定版本）
```

关键设计点：
- **触发-诊断-实验三层漏斗**控制成本：监测零标签、诊断用探针少量标签、实验才花大钱；
- **回滚是一等公民**：repair 场景（S5）与"有害更新注入"测试都要求 rollback 能自动发生；
- **审计对象是 Decision**：每个决策包含诊断、候选、预算前后、证据 run_id、护栏检查结果，
  可从任一结果数字反查到具体代码路径。

## 5. 可证伪假设与消融设计

| 编号 | 假设 | 度量 | 通过阈值（预注册） |
|---|---|---|---|
| H1 | 触发式更新在单位成本增益上优于周期重训 | 主场景流式 F1 面积 / 成本 | 同增益下成本 ≤ 50%；或同成本下增益 ≥ +3pt |
| H2 | 诊断归因显著减少无谓标签消耗 | 总标签数、无用更新次数 | 标签消耗 ≤ 无诊断消融的 70% |
| H3 | 仿射校准能以 0 标签恢复传感器老化漂移的大部分性能 | S2 场景 F1 | 恢复到可恢复上界的 ≥ 80% |
| H4 | 类别扩展在开集新故障上显著优于闭集重训 | S4 场景 macro-F1（含新类） | ≥ +10pt |
| H5 | 策略层 bandit 使后续漂移的决策更省/更准 | 第 2 轮同类漂移的决策成本/命中率 | 成本下降 ≥ 20% 或命中率 ≥ +10pt |
| H6 | 看门狗回滚在维修复位/有害更新下防止性能回退 | S5 回退前后 F1、回滚延迟 | 回滚后 3 窗口内恢复 ≥ 90% 参考性能 |

消融实验（主场景 S7 + 代表场景）：
- A1 无监测（每窗口都尝试更新）→ 成本爆炸；
- A2 无诊断（固定 `FULL_FINETUNE_REPLAY`）→ 标签浪费、仿射场景过度更新；
- A3 无规划器（随机选 playbook）→ 单位成本增益下降；
- A4 无门禁（候选直接上线）→ 出现回退，验证门禁必要性；
- A5 无策略学习（固定先验）→ H5 对比；
- A6 无回滚（关闭 watchdog）→ S5 出现持续性能损失。

## 6. 工程取舍与边界（写在答辩前，避免被问倒）

| 取舍 | 理由 | 代价 |
|---|---|---|
| 系统只用 numpy，不引 torch/sklearn | 官方评测环境"普通 CPU 即可完成"，离线可复现；无二进制依赖 | 模型容量小（本任务为预提取特征，足够；大模型任务可换 adapter） |
| 默认确定性驱动，LLM 可插拔 | token 计入成本；可复现；无额度也能跑 | 语言理解能力默认不启用，需企业赛切配置 |
| 合成基准为主 | 官方数据未发放，需要可控、可诊断的实验 | 合成与真实分布有差距（用公开工业数据佐证 + docs/09 风险节） |
| 门禁阈值是启发式 | 缺少平台统一阈值先验 | 用预注册假设 + 敏感性分析覆盖（docs/10） |
| 标注预算按条计 | 官方"标注配额"口径未给出 | 主实验做预算扫描（60/120/220 条），结论不依赖单点 |
