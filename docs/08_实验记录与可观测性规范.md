## 1. 记录对象模型（与 spec.py 一一对应）

| 记录对象 | 字段 | 语义 | 写入时机 |
|---|---|---|---|
| `RunRecord` | run_id, group, name, kind, stage, config, summary, tags, t, phase, parent_run, artifacts, created_at | 一次"实验/阶段"的元信息（≈ SwanLab run） | run 开始时 `start_run` |
| `MetricPoint` | run_id, key, step, value, t | 一个指标点（本地镜像落 SQLite+JSONL；SwanLab 上是一条曲线点） | 每 step `log_metrics` |
| `Experiment` | exp_id, run_id, t, phase, playbook, params, hypothesis, driver, diagnosis_kind, cost_est, cost_actual, metrics, status, started_at | 一次候选更新实验（playbook 执行） | `run_experiment` 工具内 |
| `Decision` | t, phase, diagnosis, chosen_playbook, alternatives, budget_before/after, cost, outcome, rationale, evidence_refs, driver, safety | 一次闭环决策（审计核心对象） | Harness driver 每轮 |
| `Trajectory` | t, phase, steps[ToolCall], final_decision, tokens, wall_s, driver, outcome | LLM/确定性驱动的完整轨迹 | Harness driver 每轮 |
| artifact | run_id, step, name, src_path, stored_path, size, sha256, created_at | 模型/图表等文件索引 | `log_artifact` |

**记录粒度**：闭环每轮可产生多条 run（monitor / experiment / evaluation / deploy / rollback），
全部以 `parent_run` 指向本轮主 run（`kind=loop`），形成完整实验树。

## 2. 命名与分组规范

### 2.1 run_id

格式：`{group}-{yyyyMMdd-HHMMSS}-{6位hex}`，示例 `main-20261116-2210-a1b2c3`。

- `group`：实验组，取值 `main`（主闭环）/`baseline`（基线）/`ablation`（消融）/
  `safety`（安全演练）/`route`（路由/策略）；由 loop 传入的 `RunRecord.run_id` 优先
  （**loop 生成则 tracker 原样返回，不改写**），为空时由 tracker 生成；
- 时间戳用本机时区；6 位 hex 防碰撞；run_id 是全链路主键（记录、artifact 目录、审计日志、
  Decision.evidence_refs、SwanLab run 映射都靠它）。

### 2.2 kind / stage

- `kind`（记录类型）：`drift|diagnosis|experiment|evaluation|deploy|rollback|loop|baseline`
  （+ 扩展 `monitor` 兼容历史数据）；
- `stage`（闭环阶段，取自 spec.STAGES + system）：`monitor|diagnose|optimize|evaluate|
  rollback|system`；
- 约定映射：monitor run → stage=monitor；diagnosis → diagnose；experiment/evaluation → optimize/
  evaluate；deploy → evaluate；rollback → rollback。

### 2.3 实验名称（name / tags）

- `name` 用**人可读**中文/英文短语：`监测@t5`、`RECALIBRATE_AFFINE@t3`、`上线v5`；
- `tags` 固定包含：类型、playbook/算法、`phase{N}`、`t{N}`、场景名（如 `S7`）；
- `config` 记录可复现所需：`playbook/params/hypothesis/diagnosis_kind/seed/scenario/...`。

## 3. 存储布局与双写机制

```
experiments/
├── runs/                                  # cfg.tracker.dir（可配置）
│   ├── tracker.sqlite                     # 主索引（可查询、可 JOIN）
│   ├── records.jsonl                      # run 生命周期 JSONL 镜像（start/finish/artifact）
│   ├── tracker_warnings.jsonl             # 降级/异常告警（append-only）
│   ├── swanlog/                           # SwanLab 离线日志（mode=local/offline）
│   └── {run_id}/
│       ├── record.json                    # 最新 RunRecord + status/summary/swanlab 元信息
│       ├── metrics.jsonl                  # 指标流（每 step 一行：{run_id,step,t,metrics,ts}）
│       └── artifacts.json                 # artifact 索引
└── artifacts/{run_id}/{step}_{name}.{ext} # artifact 实体（模型统一 .npz）
```

### 3.1 SQLite schema（`tracker.sqlite`，WAL 模式）

```sql
CREATE TABLE runs (
  run_id TEXT PRIMARY KEY, group_name TEXT, name TEXT, kind TEXT, stage TEXT,
  config_json TEXT, summary_json TEXT, tags_json TEXT,
  t INTEGER, phase INTEGER, parent_run TEXT,
  created_at REAL, finished_at REAL, status TEXT,      -- running|finished|failed|crashed|killed|skipped
  swanlab_run_id TEXT, swanlab_url TEXT, swanlab_mode TEXT, note TEXT);
CREATE TABLE metrics (
  run_id TEXT, key TEXT, step INTEGER, value REAL, t INTEGER,
  PRIMARY KEY (run_id, key, step));
CREATE TABLE artifacts (
  id INTEGER PRIMARY KEY AUTOINCREMENT, run_id TEXT, step INTEGER, name TEXT,
  src_path TEXT, stored_path TEXT, size INTEGER, sha256 TEXT, created_at REAL,
  UNIQUE(run_id, stored_path));
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);   -- schema_version=1.0.0
```

索引：`runs(group_name/kind/stage/phase/created_at)`、`metrics(run_id)`、`artifacts(run_id)`；
全部写入 `INSERT OR REPLACE`/upsert（**从不 delete**，记录不可篡改，只追加/更新状态）。

### 3.2 性能与并发

- 单连接 + 可重入锁（`check_same_thread=False`），WAL + `synchronous=NORMAL` + 自动提交；
- 实测单条 `log_metrics`（SQLite+JSONL 双写）**0.26 ms**（本机，远低于 5ms 预算；
  `tests/test_tracker.py::test_metrics_performance_under_5ms` 守护）；
- 4 线程 × 40 条并发写测试通过；批量写用 `log_metrics_batch`；
- 幂等：重复 `start_run` 同一 run_id 只更新元信息，不产生重复记录。

### 3.3 不可变与容错

- 记录写坏/写一半：JSONL 追加 + SQLite 事务（自动提交），单条失败不影响其它条；
- reocrd.json 用**原子替换**（tmp+rename）；
- `log_metrics` 的 NaN/inf 自动丢弃并写 warning；`finish_run` 未知 run_id 会自动补建
  stub 记录并告警（保证循环异常退出也有记录）；
- 所有降级/可疑情况写 `tracker_warnings.jsonl`，并在 `health()` 暴露，**绝不静默吞异常**。

## 4. 调用规范（loop/引擎必须遵守）

```python
from src.core.spec import RunRecord
from src.observability.tracker import build_tracker

tracker = build_tracker(cfg, run_ctx)          # 按 cfg.tracker.backend 构建
run_id = tracker.start_run(RunRecord(
    run_id=loop_run_id,                        # loop 生成，tracker 原样返回
    group="main", name="S7主闭环", kind="loop", stage="monitor",
    config=config_snapshot, tags=["main", "S7"], t=0, phase=0))

tracker.log_metrics(run_id, {"macro_f1": 0.82, "cost_compute": 1.2},
                    step=t, t=t)               # 每窗口/每 step
tracker.log_artifact(run_id, Path("experiments/artifacts/.../model.npz"),
                     step=t, name="model.npz")  # 自动复制+sha256+索引
tracker.finish_run(run_id, {"macro_f1_area": 0.81,
                            "cost": {"compute_units": 9.6, "labels": 128,
                                     "tokens": 0, "wall_s": 2.1}},
                   status="finished")
```

硬性规范：

1. **先 start 再 log**：每轮/每实验必须先 `start_run`（tracker 容错会自动补 stub 并告警，
   但会失去 parent/kind 语义）；
2. **finish 必写**：成功 `finished`、失败 `failed`、崩溃 `crashed`、被 kill `killed`、
   跳过 `skipped`；**失败实验也必须记录**（"全部实验完整记录"）；
3. **summary 必含成本**：`summary.cost = {compute_units, labels, tokens, wall_s}` 与实验结论；
4. **artifact 必须落盘**：模型 `.npz`、图表、配置快照；路径记录在 `artifacts` 索引；
5. **配置快照**：`config_used.json` + seed 由 loop 写入实验目录（docs/03 §6）；
6. **Decision 必须能反查**：`Decision.evidence_refs` 放置 run_id/artifact 路径；
7. 禁止在训练内层循环直接写记录（记录在内层 <5ms，但仍建议按窗口节流；
   用 `log_metrics_batch` 合并）。

## 5. SwanLab 组织与上云规范

### 5.1 模式与降级

| `cfg.tracker.backend` | 行为 |
|---|---|
| `local`（默认） | 纯本地 SQLite+JSONL，**零网络** |
| `swanlab` | SwanLab（SwanLabTracker）+ 本地镜像双写；`swanlab_mode=online/local/offline/disabled` |
| `both` | 多后端形态（当前 = SwanLabTracker，保留扩展位） |
| `none` | NullTracker（极端关闭观测，不推荐） |

`SwanLabTracker` 行为：
- `mode=online`：需 `swanlab login`（云端）；`mode=local`：本地看板；`mode=offline`：
  本地记录 + 事后 `swanlab sync` 上云；`mode=disabled`：仅本地镜像；
- **软依赖**：未安装 swanlab 或 init/日志调用失败 → `degraded=True`，自动降级本地镜像，
  告警写 `tracker_warnings.jsonl`，主闭环**无感**（测试 `test_missing_swanlab_degrades_to_local`）；
- SwanLab 是**进程级单例**（同时只能有一条活跃 run），适配策略：start_run 的第一条 run
  打开 SwanLab 会话（主 run），其余子 run 默认**挂载**到同一会话，指标以
  `{run_id}/{metric}` 命名空间记录；`attach_subruns=False` 可切 1:1 模式；
- 每个 run 的 SwanLab `run_id/url` 通过 `mirror.update_run()` 写回记录
  （字段 `swanlab_run_id/swanlab_url/swanlab_mode`），支持从本地记录跳转云端。

### 5.2 project / 实验组织

```json
{"tracker": {"backend": "swanlab", "swanlab_mode": "offline",
             "project": "zhixun-engine", "dir": "experiments/runs"}}
```

- 所有 run 进同一个 `project=zhixun-engine`（赛题要求一个项目内可分析全部迭代实验）；
- SwanLab `experiment_name` = `RunRecord.name`；`config` = 标量化的 RunRecord.config；
  `tags` = RunRecord.tags（≤8 个）；
- 指标命名：主 run 用原始 key（`macro_f1/probe_macro_f1/cost_compute/...`）；
  挂载子 run 用 `{run_id}/{key}`，在 SwanLab 中按 run_id 前缀即可筛选/对比；
- 本地镜像永远是**权威记录**（含 artifact/成本/审计字段），SwanLab 是分析与可视化层。

### 5.3 上云命令（有网/有额度时）

```bash
pip install swanlab                 # 软依赖，可选
swanlab login                       # 云端模式需 API Key（离线模式可跳过）
# 运行（offline 模式，无需网络）：
$PY -m src.cli run --config configs/swanlab_offline.json
# 一条命令同步全部离线实验：
swanlab sync experiments/runs/swanlog
# 本地看板（无需登录，local/offline 均可）：
swanlab watch experiments/runs/swanlog
```

⚠️ SwanLab 版本兼容：SDK v0.8.0 起离线日志格式变化，`swanlab sync` 与生成日志的 SDK
版本需一致（或 sync 更旧）；建议固定 `swanlab==<训练时版本>` 并在 docs/12 记录。

### 6.2 `scripts/gen_record_book.py`（《实验记录汇编》）

生成 **Markdown + xlsx**（openpyxl 软依赖，缺失时降级 CSV）：

```bash
$PY scripts/gen_record_book.py \
  --title "智训引擎·实验记录汇编（校赛版）" \
  --out-md deliverables/实验记录汇编.md \
  --out-xlsx deliverables/实验记录汇编.xlsx
```

内容结构：
1. 封面/生成时间/后端/Schema/筛选条件/总量/累计成本；
2. 实验记录规范（run_id、字段、目录、双写、审计、SwanLab）；
3. 实验总览表（全部 run：组/类型/阶段/状态/t/phase/指标数/artifact/SwanLab）；
4. 成本汇总（按组 + 合计：compute_units/labels/tokens）；
5. 分组明细（每个 run：配置、summary、关键指标、artifact 路径+sha256、SwanLab url）；
6. 安全事件（回滚/异常类单独成章，便于审计）；
7. 指标明细（每 run 最新值；完整序列见 metrics.jsonl/xlsx）；
8. 复现与上云命令附录。

xlsx sheets：`说明 / 总览 / 指标明细 / 成本汇总`。

## 7. 审计追溯规范

赛题"可审计"要求：**每个决策都能从结果追溯到代码、配置、seed、数据、成本**。链路：

```
Decision (src/core/spec.py)
  ├─ t / phase / diagnosis（归因证据）
  ├─ chosen_playbook / alternatives / rationale（决策依据）
  ├─ budget_before / budget_after / cost（成本账）
  ├─ evidence_refs → run_id / artifact 路径
  └─ safety（护栏检查结果 / escalation）
        │
        ▼
RunRecord（experiments/runs/{run_id}/record.json + tracker.sqlite）
  ├─ config（playbook/params/seed/scenario/hypothesis）
  ├─ summary（指标/成本/结论）
  ├─ artifacts（模型 .npz + sha256）
  ├─ parent_run → loop 主 run → 整轮实验树
  └─ swanlab_run_id/url → 云端实验（如启用）
        │
        ▼
代码 & 配置快照：git commit（无 git 写 null）+ config_used.json + seed
审计日志：experiments/audit/{run_id}.jsonl（sha256 哈希链，SafetyGuard.AuditLog.verify()==true）
```

审计检查清单（Lead 收尾时逐项核对）：

- [ ] 每个 `Decision.evidence_refs` 里的 run_id 都能在 tracker 查到；
- [ ] 每个 experiment run 都有 `status`（含 failed）与 `cost_actual`；
- [ ] 每个 run 的 config 含 seed 与数据场景（可复现）；
- [ ] 回滚事件（kind=rollback）有 from/to version 与触发原因；
- [ ] `tracker_warnings.jsonl` 中的降级事件均为"预期内"（如 swanlab 未安装）；
- [ ] 两次相同配置 + 同 seed 的 run 指标一致（复现性测试）。

## 9. 已知限制

1. **SwanLab 基础版本无稳定 artifact API**：模型文件以本地 artifacts 为权威，
   SwanLab 只记录指标/config/summary 与 run 映射；
2. **SwanLab 单例限制**：同一进程只能一条活跃 SwanLab run，子实验以命名空间挂载；
   若需要严格 1:1，用 `SwanLabTracker(attach_subruns=False)` 顺序跑（每条 run 一个 SwanLab run）；
3. **并发**：SQLite 单连接 + 锁可保证线程安全；**多进程**同时写同一 tracker 目录不在支持范围
   （评测只跑单进程闭环）；如需要，可为每个进程分配独立 `tracker.dir` 再合并；
4. **时间戳**：created_at 用本机时钟；跨时区合并报表建议统一用 `created_at_iso`（UTC）。
