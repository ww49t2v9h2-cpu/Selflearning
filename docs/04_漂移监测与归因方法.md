# 漂移监测与归因诊断方法（Monitor + Diagnosis）

> 模块：`src/engine/monitor.py`、`src/engine/diagnosis.py`；接口契约见 `docs/03` §4.1–4.2。
> 本文回答三个问题：**看什么统计量、阈值怎么来、为什么这样归因**。所有阈值都在
> 配置里（`src/core/config.py::DEFAULT_CONFIG` 的 `monitor/diagnosis/engine.*` 段，
> 引擎侧兜底默认见 `src/engine/defaults.py::ENGINE_DEFAULTS`），不硬编码。
> 实测数字均来自 `src/engine/eval_bench.py`（可直接复跑，见文末命令）。

---

## 1. 问题设定与硬约束

部署流按窗口到达，系统只看到 `x`（无标签），必须回答：

1. **有没有漂移**（漏报会导致性能长期劣化；误报会浪费标注/算力预算）；
2. **是哪一种漂移**（不同机制对应不同"最短恢复路径"，直接决定 playbook）；
3. **花的钱值不值**（标签与算力都是显式预算，探针也要记账）。

约束：单场景端到端 **< 5s/chunk**；`labels_total` 量级 220–260 条标签要同时覆盖
"监测探针 + 诊断探针 + 适应动作的训练/评估标签"——**标签是全局最稀缺资源**。
因此监测/诊断的设计原则是：**无标签统计量优先，标签探针只在"有性能风险证据"时买**。

## 2. 监测器：状态、参考域与触发

### 2.1 三层参考域（双门不变量）

监测的核心难点是"参考分布本身会被自适应过程改写"：如果参考域跟着漂移数据走，
就再也测不到漂移（对应配套研究中"判据自指 → 静默接受"的失效模式）。本实现把参考域
拆成三层：

| 参考域 | 内容 | 更新规则 |
|---|---|---|
| `baseline_ref` | 初始无漂移窗口（warmup 4 个 chunk，上限 800 样本） | 只在 `reset_reference()` 时写入 |
| `active_ref` | 当前"已被接受"的数据域 | **只**在门禁通过/回滚后由 `on_promote()` 写入（**双门不变量**） |
| `provisional_ref` | 已稳定但尚未通过门禁的新域 | 由稳定性检测写入，仅用于审计/上线时接受，**不参与报警** |

事件只在 `mmd(chunk, active_ref)`、`ks(chunk, active_ref)` 等**对已接受域**的统计量上
触发；被拒绝的候选数据不会写入 `active_ref`，所以"门禁拒绝 → 下个窗口仍然报同一漂移"，
系统不会静默接受一个退化域。`on_promote()` 同时完成：`active_ref ← provisional_ref
或最近滚动窗口`、清空探针参考/PH 状态、重建代理基线。

### 2.2 统计量与公式

| 名称 | 定义 | 用途 |
|---|---|---|
| MMD²(RBF) | $\widehat{MMD}^2=\frac{1}{n(n-1)}\sum_{i\ne j}k(x_i,x_j)+\frac{1}{m(m-1)}\sum_{i\ne j}k(y_i,y_j)-\frac{2}{nm}\sum_{i,j}k(x_i,y_j)$，$k(x,y)=e^{-\gamma\lVert x-y\rVert^2}$，$\gamma=1/\mathrm{median}(\lVert z_i-z_j\rVert^2)$（中位数启发式），子采样 ≤400 | 多变量联合分布漂移 |
| 逐特征 KS | 双侧 KS 统计量 $D_j=\sup_t|F^{cur}_j(t)-F^{ref}_j(t)|$，渐近 p 值 $p\approx 2\sum_{k=1}^{100}(-1)^{k-1}e^{-2k^2\lambda^2}$，$\lambda=(\sqrt{n_eff}+0.12+0.11/\sqrt{n_eff})D_j$ | 定位受影响的**具体特征/传感器** |
| 预测熵/边际 | $\bar H=\frac1n\sum_i H(p(y|x_i))$，$\bar M=\frac1n\sum_i(\max p-\text{2nd max})$；对参考窗口的逐样本熵/边际做 z 分数 | 无标签性能代理 |
| 预测直方图 TV | $TV=\frac12\sum_c|\hat p^{cur}_c-\hat p^{ref}_c|$ | 类别先验漂移代理 |
| Page-Hinkley | $S_t=\sum_{i\le t}(z_i-\delta)$，$M_t=\min_{i\le t}S_i$，$PH_t=S_t-M_t$；$PH_t>\tau$ 报警，回落至 $\lambda\tau$ 以下重新武装 | **渐变**漂移（磨损/缓慢老化） |
| novelty | $r=\frac{\mathrm{mean}_{x\in cur}\,\mathrm{dist}_k(x,\,ref)}{\mathrm{mean}_{x\in ref}\,\mathrm{dist}_k(x,\,ref\setminus x)}-1$（$k=8$） | 新故障模式/新工况 |
| 探针准确率 | 每窗口按预算取 ≤4 条 oracle 标签，$acc=\frac1n\sum \mathbb 1[\hat y=y]$（**新类标签一律算错**，即部署口径） | 唯一直接性能信号 |
| 相关系数结构变化 | $corr\_change=\mathrm{mean}_{i<j}|C^{cur}_{ij}-C^{ref}_{ij}|$ | 工况切换的潜空间旋转/重参数化证据 |

### 2.3 触发规则与阈值推导

阈值来源分两类：(a) 契约里给定的初始值；(b) 用 `eval_bench.py monitor` 在 S1–S7
上实测分布后校准的引擎配置值（`engine.monitor` 段）。实测（seed=7）：

| 场景段 | MMD² | KS 显著特征数 | corr_change |
|---|---|---|---|
| 无漂移（baseline） | −0.002 ~ 0.005 | 0–1 | 0.073–0.092 |
| 渐变磨损 S1 | 0.011–0.040 | 6–22 | 0.073–0.078 |
| 增益老化 S2/S7-P2 | 0.012–0.143 | 8–38 | 0.076–0.084 |
| 工况切换 S3 | 0.025–0.068 | 14–26 | **0.111–0.117** |
| 新故障 S4 | 0.000–0.005 | 0–1 | ~0.09 |
| 标签先验 S6 | 0.019–0.050 | 5–18 | 0.075–0.092 |

据此校准：

- `mmd_threshold_calibrated = 0.02`：无漂移 MMD² 上限 ≈0.005，漂移段普遍 ≥0.02，
  取 4× 无漂移上界。DEFAULT_CONFIG 里的 0.35 是早期占位值（MMD² 量级远小于此，
  永不触发），已在引擎配置段用校准值覆盖。
- `ks_count_threshold = 6` 且 `ks_stat_topk ≥ 0.10`：48 维中 6 个特征在 α=1e-3 下同时
  显著，单特征偶然显著概率 ≤ 48×1e-3≈5%，6 个同时发生概率可忽略；再要求平均
  D 足够大，避免大样本下的"统计显著但幅度微小"。
- `novelty_threshold = 0.6`（即距离比 >1.6）：S4 新类在 48 维噪声特征上 novelty
  增量很小（实测 ~0.00–0.01），该信号**不作为唯一依据**，只在与"探针新标签/误差集中"
  组合时使用（见 §3.2）。
- Page-Hinkley：`ph_threshold = 8.0`（累计 z 单位）。语义：代理误差 z 持续 +2σ 约 4–5
  个窗口即报警；`ph_lambda=0.1` 作为重新武装的迟滞比例。渐变磨损 S1 在 P2 起 PH
  开始单调累积，是"没有显著单窗口统计量"时的主要检测手段。
- 相关系数结构阈值 `corr_change_thresh = 0.10`：旋转类工况切换实测 0.111–0.117，
  无漂移/磨损/老化背景 ≤0.092，取中点 0.10。
- 触发去抖 `event_cooldown = 3`：一次事件后 3 个窗口内只更新统计量、不重复发事件，
  避免同一轮漂移逐窗口触发实验把预算烧光；`ref_patience=3` 判定"新域已稳定"。

**工程取舍**：MMD 的 RBF 核用中位数启发式自适应带宽，在不同特征尺度下统计量数值
不可比（这也是 DEFAULT 里 0.35 阈值失效的原因）；我们没有改 core 的 `mmd_rbf`
（它被基线套件复用），而是在引擎配置里给出重标定阈值，并用 KS/corr/探针做交叉证据。
这与 DDM/ADWIN 一类"单统计量+单阈值"方案的差别是：**多证据 + 证据组合**，单统计量
阈值只作为候选触发，最终是否需要动作由诊断与门禁决定。

### 2.4 探针预算策略（标签经济学）

初始实现每 2 窗口探 6 条标签，主配置 260 条预算会被探针吃掉 ~180 条，带标签动作
无法执行（集成期实测，见 notes）。当前策略：

1. **控制探针**：无异常时每 `probe_control_every=3` 窗口探 ≤4 条（CAP 由
   `probe_max_labels=4` 控制），用于维持性能基线；
2. **可疑探针**：出现事件、PH 报警或代理 z≥1.5 时，间隔 ≥2 窗口追加一次探针；
3. **预算预留**：探针总消耗不超过 `labels_total − max(80, 0.60×labels_total)`，
   即至少为适应动作预留 60%；剩余不足时**停止探针**；
4. **成本记账**：所有探针都走 `BudgetedLabeler`→oracle，`MonitorReport.cost` 报告
   本次新购标签数（同一 id 只付费一次，monitor/diagnosis/playbook 共享缓存）。

探针准确率的参考值只在 warmup 窗口（≤2 次探针的均值，下限 0.85）与"健康窗口"
（无事件、MMD/代理正常）缓慢 EMA 更新——防止把持续劣化吸收成新常态（"接受一切"失效方向）。

## 3. 诊断归因：8 类机制的可测证据

`Diagnoser.diagnose()` 的输入是 `MonitorReport` + 当前 champion + 历史，输出
`Diagnosis(kind, severity, confidence, affected_*, prior_delta_estimate, recommended,
evidence, cost)`。**每一类都由可测证据判定**，证据全部写入 `Diagnosis.evidence`
（审计可复核）。

### 3.1 探针证据：仿射可恢复性（covariate_affine 的核心判据）

用当前窗口的探针标签 $P=\{(x_i,y_i)\}$（复用 monitor 已购标签，不足时在诊断预算内追加）：

$$
acc_{static}=\frac1{|P|}\sum\mathbb 1[\hat y^{src}(x_i)=y_i],\qquad
acc_{affine}=\frac1{|P|}\sum\mathbb 1[\hat y^{src}_{align}(x_i; \mathrm{stats}(cur))=y_i]
$$

- `affine_gain = acc_affine − acc_static`；`recoverability = gain / max(ref_acc − acc_static, ε)`；
- 用 **McNemar 精确符号检验**判断增益是否显著：$b$=仿射后改对、$c$=仿射后改错，
  双侧 p 值按 $\min(b,c)$ 的二项尾概率计算；要求 `p ≤ 0.10` 且 `gain ≥ 0.03`
  才认定"仿射显著有效"。
- 若仿射后仍残留 `ref_acc − acc_affine > residual_tol(0.08)`，说明漂移里有仿射
  解释不了的部分 → 升级为 condition_switch/concept（见 3.2）。

为什么不用"阈值 + 拍脑袋"：32 条探针标签上 accuracy 的标准误约 0.08，0.01 的增益
不可分辨；配对符号检验利用同批样本的相关性，只对"改对/改错"的翻身样本计数，
在同样标签数下判别力明显更高。

### 3.2 类别判定优先级（确定性证据树）

按证据强度排序，先命中者胜（全部阈值见配置 `diagnosis.*`）：

| 优先级 | kind | 判据 |
|---|---|---|
| 1 | `repair` | `repair_score≥0.5` 且 MMD 对 active 参考高、对 baseline 参考低（数据回到历史基线） |
| 2 | `novel_class` | ①探针中出现 $y\ge n_{classes}^{model}$ 的新标签（比例 ≥2%）；②无新标签但 novelty 显著 + 低置信样本的 novelty 集中（error_conc>0.5） |
| 3 | `label_shift` | BBSE/EM 估计先验 `label_prior_em` 的 TV 距离 ≥0.15（或预测直方图 TV ≥0.15），**且** std 比正常、仿射不显著、准确率下降有限（<0.12）——特征关系未变，先验重加权即可 |
| 4 | `noise_inflate` | 逐特征 std 中位比 ≥1.25、噪声特征占比 ≥0.5，**且仿射校准无法把差距拉回**（否则应先做仿射） |
| 5 | `covariate_affine` | 仿射显著且几乎完全恢复（`recoverability≥0.6` 且残差 ≤0.08）；或仿射不显著但"均值漂移比 ≥0.15 / std 比 ≥1.10 + 残差小"（磨损/增益类） |
| 6 | `condition_switch` | 仿射显著但残差大（只解释了一部分）、或仿射不显著但 **corr_change ≥0.10**（旋转/重参数化） |
| 7 | `concept` | 有标签探针下准确率显著下降（>0.12）且仿射不显著、无旋转证据、无 novel/label_shift/noise 证据 → 条件分布变化 |
| 8 | `benign` | 有漂移信号但性能未受损（低置信度 0.42，交给 planner 选 NOOP/零标签动作）；或完全无事件 |

`affected_features`：covariate 类取"均值漂移最大的 top-k 特征"，其余取 KS top-k；
`affected_groups` 按 `{i: f"S{i//6}"}` 映射到 8 路传感器；
`affected_classes`：探针类召回 <0.5 的类 + novel 类索引；
`prior_delta_estimate`：EM 估计先验 − 训练先验（长度 = 模型类别数）。

### 3.3 recommended 先验（策略层可修正）

`recommended` 来自配置表 `diagnosis.priors`，排序原则是**先零标签、可跨窗口泛化的
TTA 归一化，再带标签动作**：

| kind | 首选 | 其它 |
|---|---|---|
| benign | NOOP 0.70 | RECALIBRATE 0.20 / SHADOW 0.10 |
| covariate_affine / noise_inflate | RECALIBRATE_AFFINE 0.66–0.70 | NOOP / FULL_FINETUNE |
| condition_switch | RECALIBRATE_AFFINE 0.50 | LAST_LAYER 0.22 / FULL 0.16 / RETRAIN 0.12 |
| concept | RECALIBRATE 0.40 | LAST_LAYER 0.24 / FULL 0.22 / NOVEL 0.14 |
| novel_class | NOVEL_CLASS_EXTEND 0.62 | RECALIBRATE 0.18 / FULL 0.12 / NOOP 0.08 |
| label_shift | PRIOR_CORRECTION 0.48 | NOOP 0.32 / RECALIBRATE 0.20 |
| repair | NOOP 0.48 | ROLLBACK 0.30 / RECALIBRATE 0.22 |

`Planner` 会在先验上叠加 `(diagnosis_kind, playbook)` 的 bandit 后验（见 docs/05），
所以"策略表变化"会真实改变下一轮推荐排序。

## 4. 失效方向指示器与双门不变量（配套研究 J3 映射；J1 提供"无外部信道不可认证"的必要性）

集成期实测出现过两种典型失效（见 `notes/学习_dyn3三篇_与智训引擎的映射.md`）：

1. **接受一切**：参考域跟着漂移数据 rebase，之后 15 个窗口不再触发，漏检新故障；
2. **拒绝一切**：探针/门禁噪声导致连续拒绝，系统退化为全 NOOP。

配套研究 J3（criteriond，未投稿）在同一带内攻击 r=0.99 下给出方向性终态：滚动中位数尺度到
"接受一切"、EMA 到"拒绝一切"、固定阈值两者皆不——这解释了为什么我们保留**固定阈值 + 方向指示器 +
双门隔离**，而不是在线自适应尺度。对应修复（已实现，可在审计里看到）：

- **双门不变量**：`active_ref` 只在门禁通过/回滚后更新；被拒绝的候选数据不写参考域，
  只写 `provisional_ref`（审计字段 `provisional_ref_update`）。`on_promote()` 是唯一
  参考域更新入口。
- **方向指示器**：每个窗口的 `MonitorReport.state` 记录
  `accept_rate / reject_rate / n_trigger_recent / n_accept_recent / n_suppressed_recent /
  failure_direction ∈ {accept_all, reject_all, balanced} / n_accepted_total`。
  `Watchdog.state()` 记录 `rollback_count / last_action`。审计侧可对"连续 accept_all
  但性能未提升"或"连续 reject_all"报警并切到固定阈值对照策略。

## 5. 实测校准与命中率

### 5.1 诊断命中率（`eval_bench diagnosis`，seed=7，预算充足模式）

真值标注见 `src/engine/eval_bench.py::GT_KINDS`（轻度漂移 phase 接受 `benign`——
"不动作"是正确的运营决策；混合机制允许多选）。最终结果：

| 指标 | 数值 |
|---|---|
| 全 phase 命中率（7 场景 48 个 phase） | **65.5%** |
| 触发窗口（真正发生诊断的窗口）命中率 | **71.7%** |
| S3 工况切换（4 个 phase） | 4/4 判为 condition_switch |
| S4 新故障（4 个 phase） | 3/4 判为 novel_class（P1 轻微 5% 未触发/判 benign） |
| S6 标签先验（4 个 phase） | 3/4 触发并判为 label_shift（P2 未触发：该 phase 无性能风险） |
| S7 综合（12 phase，最难的混合漂移） | 主漂移 phase 全部命中（P2 covariate、P3/P4 condition、P5/P6 novel、P7 repair、P9 covariate、P10/P11 novel） |

**主要残余误判与取舍**：

1. **轻度漂移 phase 未触发**（如 S1 P3/P4、S2 P3）：事件被去抖/性能未受损时不动作，
   从运营角度是正确行为，但机制真值上算"未识别"；
2. **S7 P11 深度漂移**（旋转+老化+新故障 10%）判成 noise_inflate：多种机制叠加时
   单一 kind 必然有歧义；GT 接受 {concept, novel_class, condition_switch}，
   实际输出的 noise_inflate 反映了 std 比 1.22 的混淆——**这一 phase 的推荐动作
   （RECALIBRATE 或 NOVEL）仍然可接受**，说明"诊断 kind 错但动作对"是可用环路；
3. **S6 标签先验漂移对本基准的 hidden macro-F1 几乎无损**（静态 1.00），即使诊断正确，
   门禁也会按"无增益"拒绝 PRIOR_CORRECTION——这正符合"先验漂移 ≠ 需要模型更新"的判断。

### 5.2 监测器成本

单窗口监测开销（d=48，ref≤800 样本，chunk 100–200 样本）：MMD≈2–8ms，
逐特征 KS≈2–4ms，novelty/feature_stats/corr≈2–3ms，模型代理预测≈1ms；
**总 <20ms/chunk**，远低于 5s/chunk 目标，因此多统计量交叉证据在本赛题算力预算下完全可行。

## 7. 参考文献与对应关系

- **DDM / Page-Hinkley / ADWIN**：单变量误差率变点检测；本文用 PH 变体做"无标签代理
  误差"与"探针误差"的渐变检测，并用迟滞+去抖控制误报。
- **MMD（Gretton et al., 2012）**：两样本核检验；本文用 RBF-MMD² 做多变量联合漂移，
  中位数启发式带宽+子采样控制成本。
